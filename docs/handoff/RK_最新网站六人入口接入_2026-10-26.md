# 基于最新网站操作优化版接入六人入口

## 基线与原因

实测正式站 `https://dbd-boardgame-8qky.onrender.com/api/health` 返回版本 **b466be5**，首页拉密卡片仍写“2–4 人”。证据为 `docs/rummikub/current-xp/site-comparison.json` 和 `production-card.png`，只读取线上页面，没有创建或改变线上房间。

拉取后的 `origin/main` 为 **e87c967**，与线上 b466be5 在拉密前端、引擎、服务器、协议方面没有差异；多出的提交只更新魔法运动员说明文件。以这个最新分支建立独立工作树 `E:/DBD-RK-XP-Current`，分支 `codex/rk-xp-current`，没有切换或改动原目录正在进行的魔法运动员工作。

线上版本已经包含 d70cd6d 的 XP 引擎。六人并非缺少后端，而是人数选项默认只展示 2/3/4，必须先从另一个“玩法”控件选择 XP 才能看见 5/6；首页仍标 2–4，容易误判为未接入。

## 本次改动

- 首页改为 **2–6 人 / Classic + XP**。
- 大厅“本局人数”直接提供 **2 / 3 / 4 / 5 · XP / 6 · XP**。
- 直接选择 5/6 人，向现有服务器一次提交人数和 `variant=xp`，自动启用 160 张；选回 2/3/4 人则提交 `variant=classic`、恢复 106 张。不需要先操作玩法下拉框。
- 房间信息明确显示当前人数、模式和牌数。保留房主权限、准备重置和不得挤出已入座玩家的服务器校验。
- 建房入口说明也展示 2–6 人。

没有替换旧版 Rummikub.tsx 或 rk.css，没有改引擎、服务器或协议。当前网站的自适应主按钮、整副手牌自动排布、横屏完整手牌、选牌后快捷建组和桌面操作优化均保留。浏览器回归改用当前的快捷建组与自适应主按钮，避免旧测试文案误导验收。

## 实际检查

- 测试先行：新增人数到模式映射测试，初始失败记录 `red.txt`；修复后拉密 UI、引擎、房间和网络针对性 **8 文件、55/55 项通过**。
- `npm test`：**65 文件、914/914 项通过，181.12 秒**。
- 真实五浏览器界面整局 **173 回合**、六浏览器整局 **131 回合**，均完成结算和下一局；两种人数都从默认经典房间直接选人数进入 XP，另外验证选回 4 人能恢复经典模式。
- 六人开局每人 14 张、牌池 76；五人牌池 90。私有手牌隔离、第三副本、J3/J4、草稿重连、实际服务器进程重启和旧经典存档恢复均通过。
- 页面错误 0；13 张截图通过页面水平滚动、名字裁切、六席边界、先手牌和操作按钮边界、图片非空白等检查，并人工查看手机竖屏、横屏和大厅截图。
- 构建、格式、类型检查通过。干净工作树首次类型检查缺少生成的 `scenarios.generated.json`，实际执行 capture 与 collect 流程后再次检查通过，没有通过修改类型或伪造 JSON 绕过。
- 回放三局一致、手机界面 64 场景通过，退出码均为 0，见 `current-xp/preflight.json`。

证据集中在 `docs/rummikub/current-xp/`，UI 截图与浏览器结构化报告在其 `ui/` 子目录。构建仍有既有大包提示。浏览器为 Chromium 手机视口，未声称完成真实手机或 Safari 验证。
