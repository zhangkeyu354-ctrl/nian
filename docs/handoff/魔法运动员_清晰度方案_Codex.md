## 可选择的五项方案

下面各项可以组合，不要求全部采用。代价指实现复杂度与屏幕占用，不是增加玩家的等待时间。

### 1. 固定解说带：同一个地方一直说清「谁 → 做什么 → 结果」

**解决什么：** 技能卡、飘字、连线分散在屏幕不同位置；连锁一长，视线需要来回找。

**怎么做：**
- 棋盘上方用一个固定位置的两行解说带，例如「小王 · 半人马【尥蹶子】」「小李 · 兔子：第 18 格 → 第 16 格」。本人明确写「你」，并保留角色名，不能只写「你的技能」。
- 解说带跟随实际播放的事件更新，在下一事件到来前保留文字；不额外排一个必须读完的阶段。
- 保留重要技能的中央大卡；同一条连锁中重复发动同一技能时，沿用固定位置并显示触发次数，减少反复进出场。只压缩重复介绍，不省略每次结果，也不跳过逐格移动。
- 摔倒、后退、淘汰仍有不同图标和文字，不只依赖红/绿颜色。

**代价：** 中。需要整理播放事件对应的展示内容；占约 44–56px 的共享信息区。已有不明确的技能来源不能凭最近一条技能猜测，应配合第 3 项的因果字段，或只写已知的移动原因。

### 2. 回合小结：播完后留下一条能读懂的结果

**解决什么：** 看完一连串动画后，不知道这一回合到底改变了什么。

**怎么做：**
- 与第 1 项共用同一位置：播放时是当前解说，回合完成后切成小结，不新增一个挡住棋盘的弹窗。
- 先写净结果，例如「小王的回合结束：你后退 2 格并摔倒；半人马前进 5 格；挪挪累计前进 3 格」。数字仅为格式示例，来自当次真实事件。
- 净位移与过程分开：即使先前进 2 又后退 2，不能只写「没变化」而漏掉中间摔倒或得分。展开后按顺序列出完整效果。
- 连锁中遇到中途选择时写「等待小李决定 · 连锁未结束」，不把一次网络响应误当整回合结束；连续行动、额外回合分别分组。
- 默认只保留最近 3 个回合，更多信息仍可从已有比赛记录查，不无限堆积 DOM。

**代价：** 中偏高。需要可靠的回合边界与事件分组；可只给现有 `fx` 增补展示用回合标识/结束标记，不改变判定流程。小结自动出现但不要求确认，不阻止下一位行动。

### 3. 「影响到你」提醒：回来后先看到自己遭遇了什么

**解决什么：** 其他人的回合没有一直看屏幕，回来时不知道自己为什么被退格、摔倒或传送。

**怎么做：**
- 显示「影响到你 · 2 条」入口；点开看「小王的半人马使你的兔子后退 2 格」「你的挪挪因对方技能前进 1 格」。两名己方角色分别写清身份。
- 区分「你的技能发动」和「你被别人影响」，两者不等同；共同移动、受益、受损均按真实事件记录。
- 提醒保留到用户查看/标为已读，不随 2.6 秒动画消失。新事件更新计数，不连发新弹窗、不增加音效。
- 手机恢复前台时，先给离开期间的摘要；不强制从头播放整段积压动画。首次加入不把所有旧历史当成未读。
- 为描述因果，在有证据的事件上加展示元数据，如来源角色、实际能力 ID、原因事件 ID、同一效果分组 ID。箭头/石头明确标为「赛道」，不能误归给刚发动技能的人；无法确认来源时写实际效果，不造原因。

**代价：** 中偏高。需要本机已读状态与少量 `fx` 因果字段及测试；不新增服务器指令，不读服务器重放快照，不改隐私权限。刷新后只能恢复已保存或现有公开记录支持的信息，不能承诺无界历史。

### 4. 本场赛况条：名次、角色、离终点几格一眼能看见

**解决什么：** 顶部总积分被误认为当前领先顺序；不清楚自己两个角色的位置。

**怎么做：**
- 重用现有压缩比分条的位置，提供明确的「本场赛况 / 总积分」切换，比赛中默认本场；累计积分仍随时可看。
- 每个角色一项：「第 1 · 小王/半人马 · 距终点 4 格」。己方固定有「我」标识，两名角色各自显示；长昵称允许省略，但详情能读全。
- 同格按并列名次显示，不凭座位顺序造领先关系；已经冲线的按真实名次显示，淘汰者单独标注。主移动距离不等于实际几回合能到，不能写成胜率预测。
- 动画播放时，排名和距离跟棋盘正在显示的位置同步；播放结束后才对齐服务器状态，避免小人还没走，顶部先显示最终排名。
- 390px 屏上默认看见己方和领跑者，其余横向滑动/展开；不再额外加一整排固定面板。

**代价：** 中。主要在前端派生显示状态；要覆盖并列、两角色、冲线、淘汰和换场。不会改变正式胜负或积分计算。

### 5. 「刚才发生了什么」只读回看（可后做）

**解决什么：** 小结仍不够，需要按顺序重新理解一段复杂连锁。

**怎么做：**
- 从小结打开最近一回合时间线：发动者 → 原因 → 对象 → 位置/状态结果；可点选任一步查看当时的棋盘位置。
- 明确显示「回看中 · 非当前局面」，不发送旧命令、不重新掷骰、不再次触发技能或结算音效。
- 实时比赛继续，提示有新进展；关掉回看返回真实局面。若轮到自己，展示返回当前操作的入口，不替玩家选择。
- 第一版推荐静态逐步查看；完整重播动画以后再决定，避免多维护一套与实时队列冲突的播放器。

**代价：** 高。需独立、有限容量的展示历史与只读棋盘状态，处理换场、重连与新事件。用户主动打开才耗阅读时间，不拖慢其他玩家。

## 推荐选择

**推荐先做 1 + 2 + 3 + 4，5 暂缓。** 这样形成：当下看清 → 回合后记得 → 离开后可补看 → 随时知道赛况。四项共用现有顶部与一块信息区，不是叠四层弹窗。

- 最小改动组合：**1 + 4**。先改善当下辨识和名次；事后回顾能力仍有限。
- 完整推荐组合：**1 + 2 + 3 + 4**。覆盖指令第 3 节的三个主要问题。
- 加强回顾组合：**1 + 2 + 3 + 4 + 5**。仅在确实需要逐步回看时采用，工程代价最大。

也可以直接选择任意编号，或指定「已有大卡完全保留，只加小结和个人提醒」等偏好。本轮不代用户选定。

## 共同的设计与实现边界

- **速度：** 不添加强制倒计时、确认按钮或全员等待；移动仍逐格播。相同公开事件序列下，新增 UI 不得增加自动播放总时长；重复说明可减少，无效果丢失。现有慢/正常/快与减少动态效果设置继续有效。
- **数据：** 小结按实际事件，而非仅比较最终位置；不能按 `why` 文案或最近一次技能推断复杂因果。若加字段，仅为 `fx` 展示用途，并补测试证明现有命令结果、顺序、随机消耗、积分、隐私规则不变。
- **手机：** 390×844、390×664 都先保留棋盘和当前操作；共享信息区不堆高。详情在用户点击后打开，最高约 60dvh、内部滚动、关闭按钮常可见，操作入口不被遮住。原版棋盘与清晰棋盘均适用，横屏不改变信息含义。
- **状态：** 尚未开始时显示「等待开赛」；无个人影响时显示「本回合未影响你」；连锁中途等待写清等待谁；重连先说明正在同步；历史不足时明确仅有当前可用记录，不编造缺失经过。新比赛清空上一场赛况，允许保留有场次标签的最近回合记录。
- **中文与无障碍：** 玩家名、角色名、动作、结果都有中文文字；我方/他方、受益/受损除颜色外还有文字和图标；详情按钮至少 44px。读屏播报使用节制的礼貌通知，不把每一步重复报一遍。
- **范围：** 不改黎明杀机和其他游戏；不改规则判定、房间命令、比赛节奏控制权。需要的代码限制在魔法运动员展示与允许的 `fx` 字段；用户选完再在 `codex/ma-clarity` 上实现。
