# 核心引擎升级方案与独立验证原型

> 下方为早期调查/方案历史。用户后来已批准采用SW-F01接入原引擎，现完成36名开发预览，实验队列未接入。当前范围、待决规则及发布限制以[最终验收报告](../../handoff/魔法运动员_36名新角色_最终验收报告_2026-10-26.md)为准，仍未批准合并或部署。


目标是扩充现有游戏，不另起大厅、后台或新实时服务。本轮**不把36份未核转录写成可玩技能**，只交付数据隔离、证据审计、队列验证原型。官方Second Wind逐角色技能通过数0/36；这不是正式升级完成报告。

## 一、兼容分流

新房间未来增加 `rulesetId`、`contentSets` 与数据版本；没有版本字段的旧存档一律走现行 `legacy-f356900` 逻辑，不能因为部署升级重放成另一套结算结果。建议候选profile为 `base-2026-reviewed` 与 `second-wind-reviewed`，只有逐项证据和测试通过后才可用；本轮没有创建这些正式选项。

先固定旧命令轨迹、RNG、积分与隐私快照，再用新旧reducer并行离线对照。后退经过、首回合双选手、摔倒时的turn-start、仅剩一名结算与奖牌序列的差异全部显式列在规则profile中，不无声覆盖。选择profile只作用于新房间；旧房间版本、资源与命令格式保留。

## 二、身份、实体与控制权

- 区分玩家/座位、卡牌定义、比赛中的角色实例、能力实例。`racerInstanceId`不能复用英文角色ID作为永远唯一的身份；Re-Runner、复制能力和混盒需要独立生命周期。
- `controllerByRacer`是当前控制权；身体的位置、摔倒、淘汰与已经完成的回合属于角色实例。比赛积分是玩家账本，不因UI换头像自动转移；交换是否转历史得分等待原规则确认。
- 固定行动列表引用角色实例，不仅引用玩家。增加 `currentRacerId`，避免Switcharoo改变owner后旧玩家循环仍执行已换走角色。
- pending保存角色ID、decisionId和控制权epoch。答题时从认证座位查玩家、再从服务端状态查当前控制者，不采信客户端 `player`、目标、骰点、效果或“已发动”标记。
- 控制交换是原子事件，更新卡牌归属、控制映射与公开徽章；不得顺带移动身体或清除tripped。尚未核实的行动顺序变更策略先阻塞，不猜。

## 三、事件队列

建议事件包含：`eventId / commandId / raceId / turnId / parentEventId / ordinal / groupId / sourceAbilityInstanceId / targetRacerIds / kind / payload / status`。ID由服务器确定性生成，不能用动画计数或浏览器时间戳。

事件类别至少分开：TURN_START、ROLL_REQUEST、ROLL_RESULT、REROLL_WINDOW、MAIN_MOVE、EXTRA_MOVE、WARP_GROUP、ARRIVAL_GROUP、PASS、TRIP、ELIMINATE、TRANSFER_CONTROL、EXTRA_TURN、FINISH_PROPOSAL、FINISH_COMMIT、RACE_CANCEL、RACE_END、SCORE_AWARD。显示fx是已确认事件的投影，不是规则输入。

1. 当前事件完整完成后，子连锁在后续兄弟事件之前依次完成；每组并发到达先整体更新位置，再按核实的顺序结算。不能逐个warp来伪装“同时”。
2. 决定点暂停。一个可提交事件最多一个决定；需要多个选择时分阶段子事件，避免恢复时重复执行前半段。
3. 回答绑定decisionId、版本与角色当前控制者。请求ID保存指纹和receipt，同请求重试可返回成功；同ID不同内容拒绝，过期版本拒绝。
4. 一个请求内模型、游标、已结算ID、随机数、答案和receipt原子持久化。先写盘再广播/ack，不能已回复成功但命令未保存。跨部署可靠性需持久盘或已有存储策略，不能拿Render临时文件保证永久恢复。
5. 动画使用独立outbox/eventId去重；浏览器断线只补看，不重新发动技能。所有积分/淘汰/骰值由server执行。
6. 批次预算只用于让出CPU，保留未完成队列，**不是规则中的连锁次数上限**。真正循环判定需含位置、摔倒、能力抑制/复制、控制者、已用次数、回合标记及影响后续的积分/牌堆等；没有进展的死锁和有限随机重掷不是同一件事。

## 四、本轮原型实际做了什么

文件：`packages/magical-athlete/experimental/event-queue.ts`。

原型有JSON可序列化状态、FIFO根事件/先子后兄弟、单决定暂停、重新加载后回答、请求指纹收据、事件ID与已回答决定ID去重、原子回滚、当前控制者查验、隐私元数据投影，以及每批256事件让出预算。11个队列测试实际通过，包括600个有限事件分三批完整执行。

**没有接入** `reduceMA`、`MARoomStore`、Socket.IO或React；handler使用测试模型，既不是Kraken实现，也不是Switcharoo正式规则。PUMP只应由server内部任务调用，未来认证适配器不得公开给客户端。后续增加 `experimental/queue-store.ts`：单进程文件适配，临时写入并flush后rename，再返回成功；6个测试验证新实例重载、保存失败回滚与重试、权限投影、路径限制和600事件恢复。它不是线上持久化升级；没有实现数据库事务、真实进程崩溃/断电测试、分布式锁、生产随机数接线、完整因果日志、真实循环检测或比赛能力处理器。`queuePublicView`只投影队列元数据，不能代替游戏状态的隐私投影。

## 五、11名重点角色的接入设计

|角色|引擎需要的能力|不能跳过的核验/测试|
|---|---|---|
|Kraken|一次性能力计数、多人WARP_GROUP、显式TRIP组|与巨婴位置调整、同时到达和复制次数交互|
|Switcharoo|TRANSFER_CONTROL原子事件、控制权epoch、动态pending归属|角色身体与摔倒保留；卡牌、行动顺序与历史分数政策待核|
|Re-Runner|跨场实体延续、额外参赛者、每玩家可变长度角色列表|首次/末场、淘汰后、换手后归属、与double叠加|
|Magical Athlete|最终骰分支处理器、替代主移动、选择窗口、额外回合|六个分支分别3类测试，不能将所有分支都解释成先move再fx|
|Show-Off|有序骰历史、继续/停止决定、失败分支、最终提交窗口|旧骰触发的可撤销性、重掷窗口顺序；允许断线恢复|
|Icarus|最终骰后的淘汰事件与主移动取消|重掷前后、唯一存活者、军师预测与新淘汰语义|
|Null|只读有效能力查询、抑制图及重新激活|不抹除基础能力；复制者与多Null位置变化|
|Speed Demon|积分读取快照、领先集合、回合开始淘汰|换控制者后读谁的积分、4格边界和只剩一名|
|Party Pooper|统一所有骰目的与全局重掷管线|main/duel/multi/power骰，连续6与固定骰冲突|
|Doppelgängster|FINISH_PROPOSAL拦截，明确冠军提交点|不能先发金牌再补淘汰；与Twin、Mastermind、返场角色交互|
|Spoilsport|RACE_CANCEL独立于正常RACE_END与奖牌结算|不默认复用endRace发金银；已得分/赛后能力的规则待核|

其余25名所需时点、效果、对象、动画、边界与互动也已逐角色登记。没有原文证据的字段只能保留candidate，不能由脚本自动生成正式技能。

## 六、上线前验收门槛

- 每名确认角色至少正常/边界/互动3类，36名最少108项真实技能测试；当前108是计划，0项角色技能已执行。
- 11名重点角色中的多骰、控制权与积分取消要更细粒度分支测试；至少逐角色与基础Copycat、Scoocher、Huge Baby、Suckerfish等交互。未测试不能标混盒兼容。
- 2–6人，draft/random，标准/合法多角色模式，完整4场模拟，检查无重复角色实体、控制者、轮次、结算与筹码守恒。
- 断线、重启、重复ACK/命令、旧decisionId、篡改骰点、同ID异内容、旧控制者提交均需真实房间测试。
- 手机/电脑选择控件与动画必须对应服务端决定；先原文确认和引擎测试，再接UI与可发布美术。新赛道逐格、拓扑、坐标和循环验收单独进行。
