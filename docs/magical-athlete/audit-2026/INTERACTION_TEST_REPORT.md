## 三、无限循环处理

判定规则（`engine.ts` 的 `loopCheck`）：同一个触发（同一来源 → 同一对象，或同一选手 → 同一箭头格）在**所有选手位置、摔倒、名次、淘汰都完全相同**的局面下第二次出现，才是真正的无限循环（规则书 Fiddly Details #8 说的 A 类）。此时已经按发生顺序结算了一轮，记一条「循环」记录后停止。

- A 类（真正重复、不改变状态）：挪挪 × 巨婴、箭头 × 巨婴 → 记录「循环」并停止，有测试。
- B 类（局面一直在变、最后能到终点）：挪挪 × 吸盘鱼 → 不停止，有测试。
- C 类（多人互相触发但有限）：浪漫者 × 挪挪、魔术师 × 骰贩子 × 挪挪 → 自然结束，有测试。
- 没有用「触发 N 次就停」当作规则。另有 20000 次的程序保险丝（MA-L01），触发时直接报错，不会悄悄停止。

## 四、整局与联机

- 随机整局模拟：3/4/5/6 人标准规则各 25 局，2 人、3 人双选手各 25 局，全部打完；每步检查隐私视图（别人看不到牌堆、重放快照、别人的待决定选项）。
- 固定种子复现：同种子同操作两次结果逐字节相同。
- 多浏览器联机（`npm run verify:ma-browsers`，手机尺寸）：2 人、3 人、4 人各从首页点进去打完 4 场。
- 重复提交：房间层用版本号拒绝过期命令（ma-rooms.test）；引擎层拒绝不是自己的决定、不存在的选项（audit「命令校验与重复提交」）。
