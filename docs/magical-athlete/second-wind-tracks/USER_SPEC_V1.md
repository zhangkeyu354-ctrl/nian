建房提供：

- 仅一代：温和→狂野→温和→狂野。
- 仅二代：扭扭→螺旋→扭扭→螺旋。
- 一二代标准混合：温和→狂野→扭扭→螺旋。
- 完全自定义：四场逐项选择任意地图；允许重复。
- 随机赛程：由服务器从已启用地图中生成，允许重复；开局前公开具体结果，房主可确认或重抽。
- 逐轮自由选图：由房主在每场比赛选择运动员之前确定本场地图，所有玩家同步看到；允许与上一场相同。当前场地图一经锁定，选角和比赛期间禁止更改。房主掉线按现有房主迁移规则处理；若没有相应机制，应有超时/回退到预先选定地图的确定性方案，并明确显示，不得卡死。

赛程配置由服务器保存和验证。保存 `scheduledRaceIndex`（正常场次编号）、`raceInstanceId`（实际比赛实例）、`raceKind`（normal / extra_final 等）、`trackId`、`direction`、已锁定规则与事件状态。临时1v1决赛不消耗下一场正常赛程、不发放新的正常场次奖杯、不额外消耗运动员选择名额、不推进正常比赛计数。正常场次的奖杯值不随地图名称变化。

房间设置、等待大厅、每场开始、比赛间歇均应清楚显示地图和剩余赛程。允许主持人修改开局前设置，不允许在已开始的正常比赛中途换图。逐轮模式只开放尚未锁定的一场。

## 4. 移动系统与事件结算框架

在现有规则引擎基础上区分以下动作，前端动画不参与裁决：

- `MAIN_MOVE`：回合的主移动（骰值及适用修正）。
- `MOVE`：实际移动，含技能/事件移动；按已有规则处理途经和超越。
- `WARP`：直接传送，不算普通移动，不产生超越事件，但到达可触发相应落点效果。
- `PLACEMENT`：赛前放置，默认不触发赛道效果。
- `STOP`：最终停在某个可停留格。
- `FINISH`, `ELIMINATE`, `TRIP`, `TURN_END`, `ROLL` 等与既有事件保持统一语义。

不要把全部变化实现成简单的 `position += n`。同一动作可能产生多个后续事件，采用确定性事件队列、唯一动作ID及来源信息。多项效果同时触发时，按现有官方规则框架：地图格子效果优先，其后当前玩家、其后其他玩家按行动顺序。已有一代事件顺序不应因新增地图而退化。

终点逻辑、角色技能、绊倒、传送、淘汰和积分处理应使用共用引擎，不复制四份比赛代码。一次移动需记录起点、目标、动作类型、实际路径、方向、所属回合与触发链。空移动/仅视觉动画不应产生真实移动事件。已经淘汰或完成比赛的实体不再执行正常移动或正常回合，除非具体规则明确允许。

对复杂结算设置可恢复的待处理状态（例如换角色选择）。不得在动画完成、客户端回包或本地计时之后才由客户端决定游戏结果。需要等待真人决策时，由服务端暂停对应状态并设置合理时限，超时使用确定的默认选项。

## 5. 扭扭赛道核心机制

- 正常方向第一次实际移动跨越13/14边界，抽一张 Twist 牌；每场仅触发一次。触发者必须可追踪到具体运动员实体及控制者。
- `TWIST` 是边界标记，不是额外停留格。判断正向 `from <= 13 && to >= 14`；如初始方向为反向，使用对称跨越检测；镜像事件不会导致再次触发。
- 传送及赛前放置不触发 Twist；负向移动是否可成为首次触发者，现有文字未明确，网站默认按比赛前进方向首次实际穿越触发，逆向移动不抽卡（HOUSE_RULING）。
- 本次位移完成后先处理 Twist 再继续落点、冲线、名次等尚未提交的效果；若事件改变了位置或方向，后续结算须以更新后的真实状态为准，不提交陈旧目的地。这个顺序为网站实现裁决，非已逐字核验的官方细则。
- 若同批多个运动员实际跨越，按当前确定的行动/结算顺序选第一位；设置已触发标志必须发生在抽卡和效果执行之前，防止并发/嵌套重复抽牌。
- 每一场新的扭扭赛道正常比赛独立洗完整13张卡，不放回抽取；“观众渴求混乱”抽取的卡按顺序执行，当前场不得重复出现同一张。此为玩家提供的实现规则；未取得正式规则书全文对逐场重洗和所有触发时序的独立确认，保留可调整的策略函数。
- 新场清除前场普通持续事件、地图上的积分筹码、怪物和固定骰值；只通过明确的跨场事件机制保留必要信息。重复选择扭扭赛道应重新建立独立牌堆与触发标志。

## 6. Twist 十三张事件卡：完整实现表

英文名称供程序ID、日志和双语核对；中文显示名可与现有术语统一，不更改效果。下列条款吸收玩家反馈及已有规则摘录，尤其修正“禁跑针对任意移动”“全体共用一个固定骰值”“当前领先两人立即重赛”等误解。

### T01 地上烤鸡！ / Roast Chicken on the Ground!

确定事件结算时仍参赛的末位运动员，令其向前实际移动7格（非主移动）。若多人并列末位，全部获得该移动，采用既有确定性结算顺序（必要时当前回合顺序）；名单在事件开始时固定，不能因首人移动而改变其他并列者资格。正确处理后续超越、停格和冲线。

### T02 镜像世界生效！ / Mirror World Theory Confirmed!

持续至本场结束，反转比赛前进方向及所有相对位置参照。原地改变方向，不把所有人坐标镜像复制，不凭空移动棋子。正常方向第一/第二弯道12/15变为15/12；相对起点、终点、领先、末位和技能中的前后全部同步反转。已处于反向终点的运动员按当前行动顺序确定冲线名次；已经完成比赛者不因方向反转而复活。现有文字支持反转与旧START并列处理；复杂已冲线情形需保留独立策略与测试。

### T03 传送带启动！ / The Conveyor Belt Is On!

所有仍参赛运动员直接传送到当前比赛起点后一格（正向1，反向29），而非普通移动；本场所有运动员主移动永久+3，不修改骰值本身，也不对技能额外移动、传送或怪物移动统一加3。后续替换/新增运动员按全场修正计算。与镜像、固定骰值、其他主移动加成同时存在时须统一结算。

### T04 禁跑水潭！ / No Running by the Scrying Pool!

只检查主移动最终应移动的格数（包含适用修正）。若主移动达到6格或以上，运动员直接淘汰，**不执行该次移动**。5格正常。不能因为技能移动7格、传送距离6格或固定骰值6本身（最终主移动可能被修正）而机械淘汰。事件生效前已完成的移动不追溯；同批事件处理须避免重复。

### T05 终点虫潮！ / Bonkbug Infestation at the Finish Line!

本场持续：停在当前终点前最后两个可停留格时后退5格。正向为28/29，反向为1/2。经过但未停留不触发，冲过终点不因途经末两格被拉回。后退属于实际移动，走既有超越/落点结算。不得重复处理同一未变化落点。

### T06 随机性消失！ / Randomness Has Randomly Ceased!

每名玩家掷自己的骰，分别记录固定值；本场余下所有受该规则影响的掷骰使用各自结果（包括非主移动的技能骰/事件骰），不是全体玩家共用同一数值，也不是让所有移动距离直接等于骰值。遵循既有多骰/多运动员模式与特殊骰面规则：可记录到实际骰子/参赛实体，避免两个骰被错误合并；怪物非玩家骰是否共享固定值，以及重掷技能与固定骰值的优先级，已有资料未明确，默认怪物用独立骰、固定结果不进行无效无限重掷，并标为 HOUSE_RULING。事件日志展示各自公开固定骰值，下一场清除。

### T07 皮纳塔破了！ / The Piñata Is Leaking!

在当前方向第一弯道之后的每个空的可停留格放一枚1分筹码，不放在有运动员的格、虚拟终点或起点区域。正向候选13–29；若此前镜像，则按当时方向取14–1。仅按放置时状态生成一次，之后停到有筹码的格即拾取、加1分并移除该筹码。经过不拾取，同格多人按结算顺序只能领取一次。后续再镜像时筹码保留物理位置。赛事结束清除未领取筹码；积分不重复加算。

### T08 人人诅咒魔杖！ / Curse Wands for Everyone!

本场持续：每个回合结束时由对应玩家掷骰，按点数跳过其后对应数量的行动顺位。按原有规则顺序计数，已淘汰及已完成者的原顺位也计入跳过的格数；多人控制多个运动员的模式逐个参赛顺位计数（适配现有引擎）。选中下一顺位后按正常活跃资格规则找到可执行回合者。跳过不是绊倒，不等于被跳过者执行过完整回合。保持回合轮转合法并记录掷骰与跳过对象，避免死循环；与固定骰值交互时走统一掷骰服务。

### T09 炼金实验室泄露！ / Alchemy Lab Containment Breach!

将 W.E.R.E.M.O.U.T.H. 怪物实体放到当前起点。此后每回合结束掷骰并沿当前方向移动；它在实际移动中超越的仍参赛运动员被淘汰。怪物不是普通玩家、不领取奖杯、不参与选角，不应被当作普通运动员触发全部角色能力。超越与停在同格应区分；传送不是超越。按用户 2026-11-26 明确裁定：怪物与 Bite Mark（咬痕）是不同实体；无论场上是否有咬痕及其变身形态，事件均生成独立怪物。事件不改变咬痕的位置、形态或行动次数，不给咬痕追加掷骰。怪物实际超越咬痕时也能淘汰它。怪物到达终点、仅剩一人或无人等特殊终局须调用现有规则的统一处理，不可卡死。未确认的怪物与其他持续事件优先级作为独立网站裁决记录。

### T10 观众渴求混乱！ / The Fans Demand Chaos!

从同场剩余牌堆依次抽取两张不同事件卡，严格按抽牌顺序逐张完整结算，包含等待玩家选择等异步阶段。前一张效果改变位置、方向、骰值或参赛状态后，第二张以最新状态执行。不能并行结算或因为出现选择弹窗丢掉第二张。若比赛已不可逆结束，保留并处理仍合法的赛后/跨场效果，不对已结束比赛再次发奖；异常交互写入裁决日志。

### T11 交换大会！ / Swap Meet!

每位玩家从合法、未使用的运动员池抽一张新运动员，可选择与当前上场者交换。选择同时锁定后统一提交；不要提前向其他玩家泄露尚未提交的决定。默认保留当前参赛槽位及其物理位置，替换角色身份、能力与卡牌绑定；已完成/淘汰者不得被无依据复活。新角色的旧角色专属临时状态及赛前能力是否重触发须走明确的策略，不重跑整场准备。保持控制者、剩余手牌/角色池、积分和参赛实体一致；拒绝使用未上线技能。超时默认不换。抽取的新角色若未采用的去向、角色池耗尽、多运动员模式选择哪一位等细节现有资料不足，默认未采用牌回到未使用池（本次事件不得被另一玩家重复抽取），多参赛者可选一名活跃运动员进行交换；记录为 HOUSE_RULING。二代角色未上线不作为本功能阻塞条件。

### T12 季终决战！ / Season Finale!

不是让抽卡时正在领先的两个人立即开始新比赛。先继续当前正常比赛；待第一和第二名实际冲线后，二者从当时比赛方向的第二弯道进行额外1v1决赛，第一名先行动。正常方向第二弯道=15，反向=12，玩家原反馈中的“第二个拐角（12格）”只适用于反向。奖杯两份价值作为决赛奖池，默认决赛胜者拿全部这两份奖杯对应分值；普通已获得的技能/筹码积分不没收。不得先发正常奖杯又在决赛后重复发放。决赛不消耗正常赛程或下一张选定地图，不重开选角。

网站实现：额外赛作为独立 raceInstance，使用同张地图及确定的比赛方向，从第二弯道放置两名运动员；保留原控制者与角色，重置绊倒及普通本场临时状态，不再次抽 Twist，保留明确跨场状态。此处的决赛继承哪些持续事件/开始类技能、原比赛取消或不足两人完成时是否取消决赛、镜像方向是否继承，是未完全核验的实现细节。默认不足两名合法完赛者则取消该附加决赛并按现有终局规则处理合法奖杯，禁止卡死；其余按本段规则实现，集中标注 HOUSE_RULING。额外比赛不要被记成下一场正常比赛。

### T13 踩到时之灵！ / You Tromped on a Time Imp!

触发本张事件的运动员被淘汰；在下一场正常比赛额外参赛，属于其玩家。通过“观众渴求混乱”间接抽到本卡，仍使用原 Twist 触发者，不能误用当前正在处理效果的玩家。复用既有多运动员控制架构，额外运动员不消耗正常选角名额。若是 Mush 等复制能力角色，已知规则说明支持保留被淘汰时拥有的能力；若相应角色已上线须实现。跨场待参赛记录只消费一次，掉线重连和网络重试不可重复添加。下一场为一代地图也照常生效。

若本场是最后一场且没有后续正常比赛，默认本卡只执行淘汰，不凭空追加计分场；若同场存在季终1v1决赛，时之灵返回延至下一场正常比赛，避免第三名运动员破坏1v1（HOUSE_RULING，原规则跨事件冲突未完全核验）。相关情况必须在规则说明与验收报告标明，后续可根据玩家反馈独立修订。

## 7. 螺旋世界规则

1. 实际停在六组通道任一端点时，触发一次对应双向传送。途经端点但不停下，不触发。赛前放置默认不触发。
2. 传送不是主移动、普通移动或超越；即使由4瞬间到6，也不能让超越奖励因中间经过其他运动员而触发。真正到达后仍处理合法的落点和同格效果。
3. 同一次落点结算链已使用的通道不得立即反向重复触发。使用 `visitedWarpPairs`/`warpChainId` 等等价方式，确保 A→B 不紧接 B→A；新独立移动再次停在任一端时可以重新触发。
4. 若其他角色的传送技能使运动员直接抵达端点，按已知“停在格子也包括传送抵达”的术语处理，可触发螺旋；禁止将“赛前摆放不触发”错误推广为“任何传送均不触发”。所有递归落点效果受独立事件链终止保护。
5. 配对位置永远使用固定物理编号，比赛方向改变不会改变管道连接。地图切换时清理通道链状态。传送动画只展示已经由服务器确认的起点/终点。
6. 不在螺旋世界加入普通Twist抽牌，不在扭扭赛道凭空加入螺旋管道。两种机制通过共用引擎工作，但地图配置独立。

## 8. 联机状态、存档与现有角色兼容性

- 房主赛程操作、骰子、随机牌堆、事件触发、换角色、传送、奖杯、淘汰和冲线都由服务器权威处理。客户端不得篡改或独自判定。
- 每个随机结果、事件卡实例、参赛实体及正常/额外比赛具有稳定ID。操作带局号、比赛实例、玩家权限、阶段、请求ID；防止重复点击、旧局请求、超时与手动操作竞争、重复发积分和同一Twist重复触发。
- 保存地图配置、当前场次、事件牌剩余/已抽序列、事件队列、固定骰、筹码、怪物、方向、待选择状态、跨场时之灵、决赛奖池、角色及控制者映射。重连恢复逻辑状态及剩余操作时限，不重放旧事件造成二次结算。
- 盘点现有角色实现，逐一列出触发词与新地图的关联：主移动加减、骰值替换/重掷、超越、停格/同格、传送、绊倒、弯道、起点/终点、淘汰/复活、换控制权、额外比赛、多实体、场次取消、额外运动员。不得以地图兼容为由禁用正常已上线角色而不说明。
- 区分玩家ID和运动员实体ID：一个玩家可因事件控制多名运动员；换角色或换控制权不得使积分、回合、奖励归错人。使用现有特殊角色系统，不新增不必要的规则分叉。
- 每场正常比赛结束后只清理应结束的状态；额外决赛不消耗正常比赛名额；未解决的跨场事件进入下一场的明确初始化流程。

## 9. 手机端体验与美术交付

保持现有游戏的高品质画风与原生手机竖屏体验。无需重做既有整体UI。新增赛程选择应尽量用地图预览卡而非长下拉列表，清晰显示四张地图、当前场次、锁定状态、剩余场次、自由选图及随机选图。四场配置允许重复地图；预设可一键应用并继续逐项编辑。

重点新增视觉反馈：Twist标记高亮、事件卡翻面与简洁中文效果说明；螺旋传送沿对应管道的动画（不得画错配对）；镜像方向切换及方向提示；固定骰值标识；怪物追赶、虫潮后退、皮纳塔筹码拾取、淘汰、换角色、决赛提示、时之灵跨场参赛。优先复用现有图标、音效、音乐及动画系统，不要求再网上搜索或下载素材。必要的简单特效可本地实现；非核心装饰找不到合适资源可省略。动画应轻量、可减少动态、不可阻塞服务端，音效遵循现有用户设置。

13张事件卡必须有独立的可辨识展示、中文说明和持续效果提示，不必等待获得13张独立高清原卡才能制作功能；使用现有参考资料制作统一的合法可用UI。美术实际产物须检查，不得拿错号、错连线的生图当作成品。提供最终地图预览图、带调试坐标截图、四地图选择页及事件/传送实机或模拟截图。原始地图艺术授权与公开发布状态分开记录。
