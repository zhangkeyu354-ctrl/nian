# 循环房规与现有引擎排查

用户裁定：局面仍在推进就继续；只有完整局面重复、后续也不可能变化时结束本场。已冲线名次和已得分保留，未冲线者无奖牌。此条是网站房规，不标为官方规则。

## 本次已实现

固定骰事件下，在每个必须执行、没有其他选项的决定边界，比较包含所有棋子、骰子来源、持续事件、玩家筹码、随机数状态和比赛顺位的完整状态。日志、版本号和只用于显示的掷骰序号不影响结算，故不参与比较。出现任意可选决定就重新开始证明。状态完全重复时结束本场；仍前进的选手不会触发。旧版比赛不增加历史字段，以保持旧存档与逐步重放完全兼容。这是当前能够证明的确定性场景，并不声称覆盖全部可能的游戏循环。

## 发现的旧保护：待用户确认，尚未修改

|位置|当前做法|可能与新房规冲突的条件|
|---|---|---|
|`engine.ts` `stateKey` / `loopCheck`（约310–358、1012、1025行）|挪挪连锁、箭头和酒店再次触发时，只比较位置、摔倒、名次、淘汰；新角色模式再比较能力来源、坐骑和牌堆长度|筹码、固定骰、持续事件或牌堆内容变化但摘要相同，可能提前停止仍在推进的一条连锁|
|`forcedTurnKey` / `proveForcedTurn`（约2114–2250行）|证明额外行动或插队循环时，忽略通常的新增铜分；重复后保留一圈分并交给下一座位|筹码每圈增加时，完整局面并未重复。此逻辑来自此前“保留一圈得分后停止重复行动”的用户裁定，新房规文字与它存在冲突|
|`romanticReaction`（约2187–2200行）|浪漫者递归反应也忽略纯新增铜分，保留一圈后停止|同上；增加得分时完整局面尚未重复|
|`forcedStandupCycle`（约2490–2546行）|强制起身在无移动、掷骰、得分和选择的闭环后结束本场；另有两名特定角色都在石头格的快捷判定|完整重放分支按完整状态比对，符合房规；但快捷判定没有逐一重放骰点，值得在修改前补证据，暂未变更|
|程序保险（`SAFETY=20000`、`advance` 1000 次、证明搜索 1024 次）|达到上限时报错或放弃证明|不会悄悄提前发奖牌，但极长的有限连锁可能报错；目前没有可复现样本|

请用户确认：此前“纯加分强制循环保留一圈分后交给下一位”的裁定是否继续作为特例；以及石头格快捷判定是否允许保持现状。确认前不改这些旧路径。
