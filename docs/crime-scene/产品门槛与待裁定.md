# 《犯罪现场》产品门槛与待裁定

日期：2026-11-20。依据：用户提供的《Codex 任务：在现有桌游网站中新增〈犯罪现场〉》全文、现有 `GameHall.tsx`、`game-hall.css`、`apps/server` 联机架构。游戏 ID：`crime-scene`。

## 1. Archetype

新游戏功能。按工作区要求依次进行 STAR、PRD、GROOVY、设计基线；用户附件已明确要求实施，实施授权成立，但仍须先完成门槛。

## 2. STAR 压力测试

**Situation**：4–12 人需要在现有桌游大厅中创建房间，用各自手机完成隐藏身份推理。当前网站没有这款游戏。

**Tension**：服务端必须严格过滤身份和答案；特殊事件与胜负规则存在未裁定交互；290 张统一插图及大量场景美术成本高；直接推 `main` 会自动上线并可能中断房间。

| 方案 | 收益 | 代价 | 判断 |
| --- | --- | --- | --- |
| 线下纸牌，网站不开发 | 无技术风险 | 无法满足联机和自动流程 | 不采用 |
| 先上线无事件的基本局 | 较早验证核心流程 | 不满足用户要求的完整规则 | 仅供内部测试 |
| 完整规则、插画和联机一次交付 | 满足目标 | 需先裁定规则并完成大量美术和回归 | 目标方案 |

**决定：Revise**，高信心。目标不变，先补齐第 5 节的规则裁定。`$prd-writer` 可继续起草，问题须保留为阻塞项。

## 3. PRD 草案

**目标用户**：4–12 人的同桌或远程朋友。**目标**：在现有大厅进入同一房间，按用户给出的完整规则完成一局，隐藏信息不泄露，手机竖屏可用。**不含**：语音、原版卡面或 Logo。

| ID | 需求 | 验收标准 |
| --- | --- | --- |
| REQ-001 | 大厅入口和房间 | `crime-scene` 卡片可建房、入房、断线按凭证恢复，4–12 人上限有效 |
| REQ-002 | 身份和发牌 | 4–12 人各配置准确；专家公开，其余身份私密；难度 3/4/5 对卡牌公开 |
| REQ-003 | 夜晚 | 凶手选择自己一对牌；帮凶和专家只见获授权答案；目击者只见两人而不见身份对应；其余人不能从数据或时长判断身份 |
| REQ-004 | 调查和简报 | 六板标记、第 2/3 轮换板、顺时针发言及计时状态由服务端验证；历史可回放 |
| REQ-005 | 破案与结算 | 同一其他玩家的一对牌；错误消耗机会，正确按目击者规则结算；全部终局分支有测试 |
| REQ-006 | 特殊事件 | 默认关闭；开启后六事件均有合法状态转移和测试 |
| REQ-007 | 隐私 | 对每种身份和重连路径检查网络载荷，不含无权知道的答案或角色 |
| REQ-008 | 美术与界面 | 复用大厅 token；简体中文、手机竖屏；原创封面、证物照片、身份和场景视觉；无原版素材 |
| REQ-009 | 上线 | 本地 4/8/12 人对局、全量回归、手机截图；用户确认后依仓库流程发布至 Render |

**数据**：线索、手段、场景、身份分别结构化；用户标注的“案发日子”“作案时长”保留 `needsVerify`。**依赖**：既有 React/TypeScript/Vite 前端、Node/Socket.IO 服务端与房间框架。**风险**：规则歧义、隐藏信息、断线时钟、插图数量、部署影响。`$groovy-alignment` 可继续，但不能把未裁定项当作已同意。

## 4. GROOVY 对齐

目标、用户、4–12 人、服务端权威、原创风格、手机优先均明确。仓库现有大厅为深色纸质卡带：背景 `#171412` 至 `#0d0b0a`、暖金强调 `#f2b544`、16px 卡带圆角、纸张颗粒和多层阴影。游戏主题可叠加蓝黑、品红、青色和警戒黄。**2026-11-20 用户追加视觉裁定**：前期写实摄影方向 AI 感过重，改参考原版的紧凑卡牌、赭红/青灰分类、暗边和简洁单物件插画；不再以写实证物照片作为卡牌主视觉。

**结论：Aligned with Changes**。用户已裁定会影响状态机、计时及特殊事件的分歧；实现者负责保密设计、测试和美术。可以进入 `$design-baseline` 并实施。

## 5. 必须裁定的规则问题

1. **已裁定**：简报从专家左边开始顺时针一圈，专家不发言。
2. **已裁定**：凶手选牌限时 60 秒，最后 15 秒醒目倒计时；超时由服务端在其公开手牌中随机选一张线索和一张手段，并私下通知凶手。其他人始终看到相同夜晚画面，夜晚结束时间统一，另加服务端随机延迟；客户端不得收到凶手选牌进度。
3. **已裁定**：所有好人破案徽章用完时立即判坏人胜，坏人徽章不计入终局条件。结算文案：“所有调查员都已失去破案机会，凶手逍遥法外”。此文案在目击者仍在场时需改为“好人方已失去破案机会”。
4. **已裁定**：反杀限时 60 秒；凶手和帮凶均可选择建议目标并互相看到，凶手提交最终指认。超时优先采用凶手当前选择，其次帮凶建议；均未选则反杀失败、好人胜。4–5 人局无目击者，不进入反杀。候选人仅调查员与目击者。
5. **已裁定**：特殊事件“证据排除”翻面的线索牌不能再指认。专家无牌，轮到专家时跳过；其余人按逆时针处理。
6. **已裁定**：特殊事件“倒数计时”本轮简报仍可破案；结束时若无人正确破案判坏人胜。第 3 轮抽到同样执行。
7. **已裁定**：“有据可寻”只能换橙色板，候选与替补均来自橙色牌堆；未选的抽牌返回堆中。
8. **已裁定**：“秘密证供”只换橙色板；“错误信息”可移动场上任意六块板（包括紫、绿）的标记。

已有明确部分：大厅沿用卡带入口；房间设置人数、难度、事件开关、专家指定；夜晚暗场；调查视角为身份卡、六板、玩家公开卡牌、发言环和破案按钮；结果页公开身份与逐轮记录。移动端需安全区、触控目标、屏幕阅读器文本、减弱动态效果和静音选项。加载、重连、专家掉线暂停、无权限、提交冲突都须有独立状态。

**状态：完成。** 案发、搜证、简报、破案、事件和结算的关键可见状态与服务端行为已定义。生产部署仍受 `nian/AGENTS.md` 的测试与用户确认要求约束。

## 7. 2026-11-20 裁定后的实现解释

- 夜晚统一结束时间应从夜晚开始计，而非从凶手提交计。所有玩家经历同一个固定 60 秒窗口和同一个服务端附加随机延迟；即使凶手提前选完也不能提前切换。倒计时仅凶手可见。此解释需在实现时验证旁观客户端无法由阶段时长推测身份。
- **已裁定**：凶手和帮凶保留与好人相同的“我要破案”入口及选牌流程。若选中真实关键证物与手法，其自己的提交按钮禁用，私下提示“不能指认真实证据，请重新选择”；服务端同样拒绝该提交，不消耗徽章、不广播任何结果。其他组合提交后按错误破案处理：全场广播“错！”，消耗该坏人徽章。服务端广播的“错！”始终对应错误组合。该私下拦截不会把答案透露给原本不知道答案的玩家（帮凶夜晚已获授权看到答案）。
- 反杀建议与最终提交必须是两个不同操作；未提交的凶手当前选择只在超时才自动生效。提交或超时都应由服务端单次原子结算，避免双重结果。
