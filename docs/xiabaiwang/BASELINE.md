# 瞎掰王开发基线（2026-10-23）

## STAR — Proceed

熟人远程语音需要网站负责秘密身份、原创题目与计分。已有平台可复用，不增加服务器。比较：纯语音手工主持零开发但易泄密；只做身份抽签无法满足结算重连；独立平台增加维护且违反用户边界。采用现有服务器上的独立游戏模块。
三项主要风险：秘密答案泄漏（开发负责按身份投影与测试）；计分版本差异（开发查证、规则页明确版本）；并发娱乐事件阻塞规则（独立事件、限流、批处理）。PRD 输入为用户两轮完整范围及明确开工授权。

## PRD

目标用户：3–10 名朋友，手机浏览器加外部语音。流程：大厅选游戏、建房加入、房主开始、秘密看角色、自由讨论、猜测者可质疑一次、最终指认、公开结算、房主下一轮、每人轮任猜测者后最终排名。

| 需求                         | 验收                                                                    |
| ---------------------------- | ----------------------------------------------------------------------- |
| REQ-001 复用大厅和 Socket.IO | 原入口保持，新增 xb 命名空间                                            |
| REQ-002 3–10 人身份          | 一猜测者一老实人，其余瞎掰人；服务端随机                                |
| REQ-003 秘密投影             | 只有老实人收到本轮答案，公开前无他人角色或未来题库                      |
| REQ-004 自由讨论             | 不强制顺序，不提供语音；当前发言者仅自愿指示                            |
| REQ-005 质疑                 | 猜测者一次、不可撤销、目标禁言但可被指认；按用户 +1/-1/-3 计分          |
| REQ-006 指认及结算           | 公开全角色和答案，记录逐轮分差及累计分；顺序轮换                        |
| REQ-007 娱乐互动             | 全员可用，2秒冷却；不写规则状态；批次广播，最多保留20个动画；可关闭音画 |
| REQ-008 重连                 | token恢复座位，快照持久化，刷新/重启不重新分配                          |
| REQ-009 手机操作             | 基础可操作布局、固定底部、确认指认与质疑，目标头像选择                  |
| REQ-010 回归                 | 3–10人逐个整局模拟、越权和泄密测试、已有测试全跑                        |

不含：内置语音、强制发言稿、强制轮流、AI鉴谎、商店。具体UI美术后续由用户指定；现在仅功能界面。原创题库文字自行编写，事实来源记录且只在服务端导入。

## GROOVY — Aligned with Changes

用户拥有最终范围与视觉决定，Codex负责实现验证。以用户明确授权为依据开始；默认每人任一次猜测者为一局，明确标记线上轮换方案。基础计分的官方原文尚未找到：开发测试暂用“猜中双方+D，猜错被选者+D”的候选公式，规则页显式标记 CHECK_REQUIRED/待核；不声称官方、不部署，待证据核定再验收。质疑公式已获用户明确指定。可进入设计基线。

## Design baseline

界面状态：连接中、入口、昵称加入、等待人数、讨论、确认目标、揭晓、最终排名、离线重连、错误。先展示题目/难度/猜测者，再个人角色与私人答案，再全体头像/连接/禁言/自愿发言指示。猜测者底部三按钮，其他人一按钮。目标确认显示昵称与不可撤销提示；无目标、冷却、离线或请求中禁用。禁言为外部语音约定，不请求麦克风。不能阻止禁言者娱乐互动。
手机320px起无横向溢出，按钮至少44px，底部safe area与正文留白，语义按钮、焦点可见、aria-live反馈、减少动态偏好；不依赖颜色表达角色。关闭动画保留文字互动提示，声音默认关闭。沿用项目字体，暂不定新品牌视觉。所有题目难度为原创编辑分级，并非原版卡难度。
实现允许：用户已明确开工；视觉留待后续。生产main为自动部署分支，独立分支本地测试，不推送main。
