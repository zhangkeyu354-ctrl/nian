# 手机竖屏布局修复 · 2026-10-25

基线：main `ec71245`。分支：`codex/xb-layout-fix`。仅瞎掰王呈现层与验收脚本，未修改引擎、计分、题库或联机协议。

## 证据

- [修改前后对比](before-after.png)：6 人讨论与终局；左为真实基线构建，右为本次修复。
- `before/`、`after/`：各 16 张截图，6/10 人 × 讨论/指认/揭晓/终局 × 390×844/360×740。
- `before.json`、`after.json`：48 组浏览器实测区域尺寸，包含 3/6/10 人和横屏、平板。
- `frozen-files.json`：冻结逻辑文件相对基线的校验记录。

390×844 的 3/6/10 人讨论阶段：舞台 584px（69.2%）、座位 76px、操作栏 128px、顶栏 56px。终局：舞台 728px（86.3%）、座位隐藏、操作栏 60px。

手机座位固定单行，可横滑并自动露出自己/当前发言人；发言时间复用原计时数据，显示为头像进度环。看身份、闭眼、本轮真相与终局隐藏座位条。终局使用现有排名，前三名含并列完整展示，其余名次为舞台内列表；回顾入口位于舞台。

## 复现

先 `npm run build`，再运行 `npm run verify:xb-layout`。可设置 `PW_CHROME` 指向本机 Chrome/Edge。脚本启动独立临时房间服务，无需生产环境。

检查包含：两种手机尺寸下舞台至少 60%、座位不超过 84px、无页面横向滚动、终局头像完整可见、34px 安全区、自己及被点名发言人的自动横滑。844×390 与 768×1024 的顶栏/舞台/座位/操作栏区域逐项对比基线，保持一致。

浏览器设备模拟与安全区样式模拟已覆盖；没有把模拟结果作为真实 iPhone 实机验证或性能测量。
