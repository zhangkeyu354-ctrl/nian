# 女巫镇M1设计基准

来源：02-prd、03-alignment。用户已经明确批准实施。

流程：建房（4～12容量）→昵称加入、取得私人凭证→准备→房主开始（实际人数决定配置）→原子生成身份、公开人物、手牌、牌堆→黎明待处理。M1只提供服务端及自动化协议操作，不显示可玩整局假按钮。

状态：空大厅；等待4人；等待准备；开始成功；非法人数/凭证/版本错误；规则证据CHECK_REQUIRED。错误不改变状态，不消耗卡，不泄露其他秘密。未登录只允许公开投影；有凭证也只能操作对应本人；房主不能窥视其他身份。

API工作流：wt:create/join/claim/action/update，同一Socket.IO实例。变更包含requestId及期望version，先授权和幂等检查再验证版本、复制计算、原子写临时文件重命名，成功后替换内存并按客户端单独投影。断线只改变连接计数，不改变身份；token重连、进程重启加载快照恢复。

稳定ID只用于服务器牌实例与本人手牌；公开隐藏身份只发数量，无全局牌ID或种子。人物公开、阵营历史私有。初始黑猫不预设所有者，必须等黎明操作。非法阶段拒绝未知命令，不使用空效果能力。

后续UI：月夜深蓝紫小镇、木桌烛光与羊皮纸原创素材。4～6宽松、7～9常规、10～12紧凑圆桌+点头像详情；底部手牌可放大、按钮≥44px、中文可读、键盘与减少动画支持。秘密操作仅本人可见，其他人统一等待。

在线改编：奇数剩余牌堆上半取floor、下半取ceil，夜晚随机插入下半（含末尾）。此为明确算法约定，不称官方规定奇数拆法。多人女巫协调/超时继续见在线改编报告，M1不执行。

约束：不改DBD引擎及其他游戏；不开新服务；不开候选数据默认开关；不推送、不部署。Implementation allowed: Yes（用户V1.0）。
