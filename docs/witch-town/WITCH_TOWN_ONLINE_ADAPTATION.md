# Salem 1692：手机联机交互改编提案
**本文件全部是线上映射提案，不是Facade Games新增规则，不是已获实施或部署授权。**
标准规则事实见[矩阵](WITCH_TOWN_RULE_MATRIX.md)，待官方澄清的机制问题仍保留在X01～X12，不能借交互设计代裁。

| ID | 原版事实/依据 | 线上提案 | 与原版的边界 |
| --- | --- | --- | --- |
| O01 | 主持人保管秘密，P3/P10～11 | 服务器担当主持；公共态与每人私态分别投影 | 不把其他人的牌下载后CSS隐藏；不要求一名玩家退出做主持 |
| O02 | 女巫共同指一个对象，P11 | 女巫私密目标板，意见一致才锁定；分歧保留协商，不默认多数/随机 | 最终目标生成协议需对齐；无主持模式20秒提示可显示，超时不自动杀人 |
| O03 | 警长不可自保，P12 | 私人保护选择器过滤自己；对非警长同样展示公共等待阶段 | 是否有“放弃保护”按钮取决X05官方澄清，不用UI偷偷改规则 |
| O04 | 自白在揭目标前，一柱沙漏P8 | 所有活人同时获得30秒自白窗口，选身份并明确提交；目标先保持隐藏 | 自动代人自白会翻牌改变游戏，禁止；官员免翻次数须显式选择 |
| O05 | 阴谋同时取左邻隐藏牌，P6 | 所有选择基于同一服务器快照，收齐后一次提交，再私下展示新身份并洗隐藏顺序 | 邻居因首步死亡如何确定依X04，不采用网络先后顺序代替规则 |
| O06 | Tituba两柱沙漏，P2/图06 | 只有她看见可排序牌堆，60秒临时编辑，确认后一次提交，结束销毁客户端临时缓存 | 拖动只是交互；未提交超时恢复还是采用最后草稿需设计明确，不能声称原规则已定 |
| O07 | 取身份与阴谋后洗混，P6/P9 | 显示位置token与实例ID分离，洗混后更新位置token并使旧选择失效 | 客户端不能跟踪稳定隐藏实例ID推断换牌轨迹 |
| O08 | 每夜分半混Night，P8 | 明确奇数堆分半约定并在profile中记录；用服务器随机源，测试可注入种子 | floor/ceil划分是线上协议；不改“下半堆”成固定底或全堆随机 |
| O09 | 4～12人各自秘密操作 | 4～6宽松/7～9标准/10～12紧凑桌；玩家面板放大，手牌单独浏览，目标带姓名确认 | 不能通过删人、少发身份或缩到文字不可读来适配 |
| O10 | 三个英文last words后静默，P9 | 中文遗言在文字/语音中如何对应词数单独约定；出局玩家可进入隔离旁观 | “三个字”不是直接等价翻译；旁观信息不得返回活人交流 |
| O11 | 桌游无网络断线约定 | 临时断线暂停当前必要秘密选择，重连恢复自己的待操作；重复命令只结算一次 | 不自动翻身份、投票、托管出牌或判负；永久断线结束/托管需独立产品方案 |
| O12 | 实体出牌落定不撤回，P9 | 确认按钮前可编辑，服务器接受后提交不可撤回；非法命令不消耗牌 | 软件合法性与事务检查不是原版额外惩罚 |

适配验收：任何客户端请求都需阶段/权限/版本校验；重复与乱序不能多次抽牌/转身份；公共事件不暴露谁具备秘密操作资格。隐藏阶段应避免通过提交人数、时长、音效或错误信息泄露角色。
这套提案可供后续groovy-alignment与design-baseline对齐；当前只形成可评审文档，不创建产品功能、不开服、不部署。
