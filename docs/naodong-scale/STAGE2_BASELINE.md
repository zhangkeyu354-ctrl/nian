# 阶段 2 实施依据（2026-10-31）

## STAR：Proceed

S：用户要把已经确认身份、规则并审核过内容的 Top Ten 做成朋友语音游玩的中文游戏；当前只有审核页，没有可执行规则。用户明确说「继续下个阶段」，题量以后再补。

T：最高风险是秘密数字泄露、把团队容错算成个人分数，以及固定整套排序与原版逐次翻牌的差异。另有 9 人专家模式缺少队长数字、重复命令、题库未来扩充的依赖。证据来自 MASTER 的最高优先级结论、法语规则矩阵、两轮真实审核和当前用户授权；不把语音内容可被程序自动判断当事实。

A：手工主持无需引擎但不能保障隐私和重放；只做基础引擎范围更小但遗漏已要求的专家变体；直接做联机 UI 能更快看到页面但越过用户分阶段边界。选择独立引擎、完整基本规则及可用人数内的专家模式，联机和界面留后续。

R：Proceed，规则与用途明确。前三风险由规则测试、不可干扰的私密视图测试、显式适配记录控制。PRD 输入：现有 RULE_MATRIX、79 道内容、阶段 2 总指令；可以进入 prd-writer。

## PRD：已具备实现输入

目标用户：4–9 人语音聚会玩家。流程：选队长/模式→每轮二选一→秘密发数字→队长先回答→其他人回答→锁定排序/专家精确猜→逐个揭示→失误转移标记→换队长→五轮或标记耗尽结束。

| 需求 | 验收标准 |
| --- | --- |
| REQ-001 准备与随机 | 固定种子可复现；默认普通基础模式、尺度放开；首位队长可指定；5 轮，每轮 2 道未重复候选，79 道足够，不自动补题 |
| REQ-002 基本规则 | 4–8 人含队长回答，9 人队长不回答；数字唯一 1–10；只比较相邻翻牌，失误耗尽立即全队失败；五轮后仍有标记全队成功 |
| REQ-003 语音与锁定 | 引擎只记录回答已完成，不保存文本或录音，不自动审核语义；队长先回答，其他人自由顺序；完成后锁定，不能改 |
| REQ-004 排序适配 | 基本模式由队长提交完整不重复座位顺序，锁定后逐次揭示；该顺序不可修改；明确这是已选线上适配 |
| REQ-005 专家变体 | 默认关，4–8 人可开启；猜精确数字、无升序惩罚；队友共同猜队长数字可恢复一枚现有便便标记；9 人拒绝该未定义组合 |
| REQ-006 幂等与校验 | 每座位 seq 严格递增；重放已成功相同命令不再执行，不同载荷复用 seq 拒绝；非法操作中文错误且不改变输入状态 |
| REQ-007 隐私与事件 | viewForND 仅本人数字与已公开数字可见；未来题目、未发数字、随机状态与命令记录不暴露；公开事件支持逐张回放 |
| REQ-008 不变量与模拟 | 每次成功 reducer 后断言数字/标记守恒、无重复及阶段权限；基本 4/6/9 人各 200 局到终局，专家 4/6 人另作覆盖，记录种子 |

范围：独立 TypeScript 引擎、首批题库批准清单、测试、模拟、规则追踪和交接。排除：服务器、Socket.IO、持久化、计时、断线、正式 UI、个人分数、排名和新题创作。不引入新分析平台或采集语音。通过规则矩阵与命令测试计数验收。可以进入 groovy-alignment。

## GROOVY：Aligned with Changes

用户拥有规则与内容决定权；Codex 负责实现和验证。用户最新授权是继续阶段 2，当前 79 道包含已按意见修改的一道，作为首批引擎内容；不再因原 150 题目标阻塞。

决定：先锁定排序作为已选适配；队长左手邻座映射为座位递增；专家默认关且不支持 9 人；不增加超时规则。79 道组成候选池，每局随机取 10 题，依序组成 5 张虚拟主题牌，每张二选一，两题一旦成为候选就不在同局其他轮出现。

风险所有者：Codex 对隐私、幂等、守恒和测试证据负责；用户负责以后题库扩充与玩法体验反馈。规则依据与适配分别记录，不声称线上排序过程与实物逐次选择完全等价。开放问题仅涉及后续联机/视觉设计，不阻塞纯引擎。可以进入 design-baseline。

## 非 UI 流程与 API 基线

状态：CHOOSE_TOPIC→ANSWER→ORDER→REVEAL→ROUND_END；专家由 ANSWER→EXPERT→CAPTAIN_GUESS→ROUND_END。任意失误耗尽立即 FINISHED；完成第五轮也 FINISHED。ROUND_END 由当轮队长确认后轮换。

createND 返回服务端状态。reduceND(state, cmd) 返回新状态或抛带中文信息的 NDGameError；无效命令不消费 seq，不修改原状态。viewForND(state, seat) 返回独立复制的白名单视图。数字牌只在题目选定后发给答题者；9 人队长无牌。每次已公开揭示产生一个公开事件，不预先把后续数字写入公开事件列表。

seq 是座位内的已接受命令序号，从 1 开始。所有成功命令保留规范化指纹以识别重试；相同已接受命令返回当前状态，不倒退，不重复事件。

团队界面后续只使用轮数、独角兽/便便标记、已公开翻牌与最终团队评价。专家模式的集体猜测由一名非队长玩家代表提交，代表必须先在语音中取得共识；引擎不能判断语音共识，帮助文字须明确。没有本阶段 UI/响应式页面。

实施授权：用户本轮明确要求继续下一阶段，已覆盖上述阶段 2 范围。前置记录已根据现有决定补齐，可以按 tdd-builder 开始。阶段 2 完成后报告停止，不进入阶段 3、不推 main、不部署。
