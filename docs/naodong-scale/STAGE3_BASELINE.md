# 阶段 3：联机协议与非 UI 基线

用户已明确验收阶段 2 并授权本阶段，不补题，使用已批准的 79 道。

沿用阶段 2 的压力测试、需求与对齐结论，扩展既定联机范围：建房/旁观加入/入座、房主设置、准备与开始、服务器权威 reducer、序号与版本、JSON 快照、token 重连及进程重启恢复。无正式 UI、计分变化或部署。

## 需求与验收

- NET-01：事件统一 nd: 前缀；只发送座位白名单视图。请求携带 room code、token、version、外层 seq、round、action；座位由已绑定 token 派生，拒绝客户端 actor/seat/now、未知字段。
- NET-02：房主设置 count 4–9、seconds 0/60/120、scale open/normal、expert 默认关、firstCaptain。默认不限时/放开，普通题池不含 spicy。修改设置清除准备，开局后设置锁定。
- NET-03：保留原版五轮，不提供任意轮数设置。9 人专家组合拒绝。正式环境只由服务器产生种子；仅测试显式 allowFixedSeed 时接受固定种子。
- NET-04：每座位外层 seq 包含大厅与对局命令，重连/重开不清零；相同请求幂等，不同载荷复用序号拒绝。规则引擎内部 seq 由服务器生成。并发 READY 可接受同轮合法旧版本，其余命令要求最新版本。
- NET-05：服务器 clock 决定 deadline，客户端不能指定时间。默认 0 不限时。可选计时仅为阶段提醒：到时设置 expired、增加 timeoutCount、保存并广播；不跳过、不猜数字、不改队伍标记或已提交内容。EXPERT 每次猜测为新计时窗口，ANSWER 中部分 READY 不延长阶段时间。
- NET-06：原子临时文件 + rename 保存，mode 0600；写失败回滚内存与版本，不返回内部路径。加载校验 schema、设置、凭证与引擎不变量；损坏文件仅记录文件名，不打印秘密。ND_DATA_DIR 默认独立于静态目录。
- NET-07：token 重连仍是原座位，READY、数字、锁定顺序、翻牌进度、seq 和 deadline 保留；无凭证不投影数字。服务器重启恢复同一 JSON 状态，超时提醒不重复触发。
- NET-08：真实 Socket.IO 协议与独立浏览器上下文各完成 4/6/9 人全局，覆盖非法操作、锁后修改、超时、断线、存档恢复和每个接收座位的隐私；运行用户指定四项回归。

## 风险与决策

最重要风险：token 混用、广播完整 state、超时改变合作规则。Codex 负责传输绑定、独立包投影比较与超时前后状态断言；用户负责后续体验反馈。当前默认有依据且已记录，不需要重复审批。

超时规则来自 CHECK_REQUIRED Q05 的既定默认，而非伪称法语原版。窗口结束后继续等待玩家，可完成后进入下一阶段；不做无限自动轮转。房间最多五轮，掉线不出座、不开新数字。

## 基线状态与界面边界

大厅状态为 state=null；游戏状态直接采用阶段 2 状态机。snapshot 顶层含公开设置/座位连接状态、mySeat、nextSeq、serverNow、deadline/expired/timeoutCount 与 viewForND 投影。token 只在入座应答给该连接，不出现在广播或玩家列表。

协议验收 HTML 只位于 scripts/fixtures，由临时 loopback 测试服务器提供。它使用真实 socket.io 浏览器客户端、原生提交按钮和只读 JSON DOM，不是正式游戏页面，不加大厅入口、游戏美术或生产前端路由。浏览器网络帧和 DOM 都与该版本、该座位的服务端投影核对。

实施授权：用户本轮明确要求执行阶段 3。使用 tdd-builder 先写失败的房间测试，再实现；完成后报告停止，不进入阶段 4。
