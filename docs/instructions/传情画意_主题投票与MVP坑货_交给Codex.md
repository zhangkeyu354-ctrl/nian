## 1. 用户要的两件事

**A. 开局投票选主题（主题只是提示，题目由大家自己写）**

开局先全员投票选这局的主题，然后每人**按这个主题自己写**一句题目。

选项共 7 个：
- 影视
- 成语
- 童话故事
- 动漫
- 歌词
- 随机
- 自定义

规则：
- **影视 / 成语 / 童话故事 / 动漫 / 歌词**：只是给大家的方向。写题目页显示"本局主题：歌词"，每人自己出一句属于这个范围的题目，比如主题是歌词，就写一句自己想到的歌词。**没有系统题库，服务器不替任何人出题**，也不检查题目是否真的属于该主题。
- **随机**：服务器从上面 5 个主题中随机选一个，之后同上。
- **自定义**：没有主题限制，和现在的流程完全一样。
- 选完主题后，写题目阶段照旧是 60 秒，之后画、猜的流程不变。

**B. 揭晓时投票选 MVP 和坑货**

揭晓时，房主仍按"题目 → 画 → 猜 → 画 → 猜 …"一页页翻。每一本传话本**翻完最后一页**后，进入这本传话本的投票：

- **本轮 MVP**：画得最好、猜得最准、最让人佩服的人。
- **本轮坑货**：画得最离谱、猜得最歪、把整条链带偏的人。
- 候选人：这本传话本里**写过题目、画过或猜过**的人。自己不能投给自己。
- 每人各投 1 票，也可以"弃权"。
- 全员投完，或 30 秒到时，公布这一本的结果，然后房主翻开下一本。

一局结束时，结算页汇总全场：
- MVP 票最多的人 → "全场 MVP"
- 坑货票最多的人 → "全场最佳坑货"

## 2. 规则细节（默认做法）

### 主题投票（阶段 `THEME`）

| 项目 | 做法 |
|---|---|
| 时长 | 30 秒 |
| 投票 | 每人 1 票；投后锁定，不能改 |
| 何时结束 | 全员投完，或到时 |
| 计票 | 最高票胜出。平票时由服务端随机（用独立种子，写进存档，可复现）。全员弃权 = 随机 |
| 投票保密 | 投票中只公布已投人数，不公布谁投了什么。自己的选择只有自己看得到 |
| 结果展示 | 选出后，全员看到 1.5 秒的结果横幅（例如"本局主题：成语"），再进入下一阶段 |

### 写题目页

- 投票结束后进入现有的 `PROMPT` 阶段。笔记本卡片标题改为"写一句「歌词」类的题目"，输入框的提示语按主题变化（例如歌词："写一句你想到的歌词"；成语："写一个成语"）。自定义时保持现在的文字。
- 主题名保存在游戏状态里，揭晓页和结算页都显示"本局主题：歌词"。
- 不新增题库文件，也不新增题目内容的校验。现有的 40 字长度限制不变。

### 揭晓投票（阶段 `REVEAL` 里的子状态，或新阶段 `AWARD`，二选一，交接里写清楚）

- 投票时机：当前传话本最后一页翻开之后，房主看到的按钮从"翻开下一页"变为投票界面。
- 候选人：这本传话本里所有 `entry.author` 去重后的人。投票人不能投自己。
- 投票方式：每人一张 MVP 票、一张坑货票。MVP 和坑货**可以投给同一个人**。可以只投其中一个，另一个弃权。
- 结束条件：全员两项都提交（弃权也算提交），或 30 秒到时，未投的人算弃权。
- 公布：只公布这一本的结果——谁得了 MVP、谁是坑货、各自几票。平票就并列显示。
- 投票是否匿名：**默认匿名**，只显示票数，不显示谁投了谁。（写进"待用户确认"）
- 公布后，房主点"翻开下一本"继续。
- 掉线的人不阻塞流程：到时自动按弃权处理。
- 房主离线可接任：沿用现有逻辑。

### 全场结算

- 汇总每本传话本的票数：MVP 总票数最多的是"全场 MVP"，坑货总票数最多的是"全场最佳坑货"，平票就并列。
- 结算页每个人显示 👑 MVP 票数和 🕳 坑货票数（图标用现有 SVG 风格自绘，不要用 emoji 作主视觉）。

## 3. 服务端与协议（必须服务端权威）

需要修改的文件：
- `packages/drawing-party/src/index.ts`：状态、动作、视图。
- `apps/server/src/drawing-rooms.ts`：超时、快照。

新增动作：
- `{ type: "THEME_VOTE"; theme: 0..6 }`（0–4 是 5 个主题，5 = 随机，6 = 自定义）
- `{ type: "AWARD_VOTE"; chain: number; mvp?: string | null; dud?: string | null }`

要求：
- 投票带 `op` 幂等标识，scope 带阶段和传话本序号。
- 重复提交、非法候选人、投给自己、阶段不对，一律拒绝并给出中文错误。
- 超时由服务器 deadline 推进，客户端不能推进。
- 视图 `viewFor`：
  - 投票进行中，不下发别人投了什么，只下发已投人数和"我投了什么"。
  - 公布后才下发这一本的计票结果。
- 快照、恢复：投票状态、平票种子都要写进存档。重启后恢复到原投票界面，计时继续。
- 不改 fa 的任何状态机路径。fa 的现有测试必须原样通过。

## 4. 界面：必须完全沿用现有画室的视觉体系

**禁止**另起一套风格，**禁止**出现普通网页表单感。全部复用以下现有内容：
- `apps/web/src/drawing/studio.css` 的变量：`--wall-*`、`--accent`、`--glass`、`--spring` 等。
- 现有组件：`.st-btn` / `.st-primary` / `.st-gold` / `.st-ghost` / `.st-pill` / `.st-chip` / `.st-check`、`.st-banner`、`.st-stamp`、`TimerRing`、`Portrait`、`CategoryIcon` 的线条图标画法、`feel()` 音效与震动。
- 传情画意保持紫色绘本画室的主题。

### 4.1 主题投票页

- 参考伪画家现有的主题投票 `.st-category-grid`：7 张卡片，横屏排成 4+3 两行、竖屏排成两列，每张卡片上面是线条图标，下面是文字。
- 在 `StudioArt.tsx` 里新增 7 个同风格的线条图标：
  - 影视：胶片
  - 成语：卷轴或印章
  - 童话故事：城堡
  - 动漫：对话气泡加星星
  - 歌词：音符
  - 随机：骰子
  - 自定义：铅笔
- 卡片底色用传情画意的纸色，选中后用薄荷绿 `--accent` 高亮，配合 `.st-check` 打勾和 `feel("select")`。
- 底部 `.st-pill` 显示"请投票选择主题 x/N"。
- 结果出来时，用 `.st-banner` 显示"本局主题：成语"，同时 `feel("turn")`。
- 写题目页的笔记本卡片上，加一个主题小标签（和画画页顶部的题目纸条同一风格），例如"本局主题 · 歌词"。

### 4.2 揭晓页的投票

- 当前传话本翻到最后一页后，在相册下方升起一个面板。样式参考伪画家投票的 `.st-vote-sheet`，颜色换成紫色玻璃。
- 面板分两行，分别是 **MVP** 和 **坑货**。每行是候选人头像卡（样式同 `.st-voter-grid`），标签写"本轮 MVP"和"本轮坑货"。每行末尾有一个"弃权"小按钮。
- 两项都选好后点"确认投票"，盖章 `.st-stamp`，并 `feel("stamp")`。
- 投票时上方的相册**仍可左右翻看**这一本，方便边看边投。
- 公布时有一个约 1.5 秒的动画：
  - MVP 头像戴上金色王冠，`feel("win")`。
  - 坑货头像上扣一个"坑"字章或冒出一个坑洞，`feel("lose")`。
  - 两者都显示票数。
  - 然后房主看到"翻开下一本 →"按钮。

### 4.3 全场结算（`Results.tsx` 的 `TaleResult`）

- 顶部新增两张大卡：
  - "全场 MVP"：金色，王冠，头像，总票数。
  - "全场最佳坑货"：紫粉色，坑洞或铲子图标，头像，总票数。
  - 动画和撒彩带沿用 `FakeResult` 的节奏。
- 原来的"起点 → 终点"传话本卡片保留，每张卡角落标出这本传话本的 MVP 和坑货的小头像。

### 4.4 适配
