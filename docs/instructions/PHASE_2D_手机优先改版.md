# Phase 2D：手机优先改版（给 Codex 的正式指令）

> 用户原话：这个网页最主要的用途，是我和朋友**在手机上玩**。现在在手机上完成一个操作还是很麻烦，不流畅。
>
> 本阶段只改"怎么玩起来顺手"。**规则引擎、联机协议、隐藏信息逻辑（privacy.ts）、游戏数据一律不改。** 物品效果、复杂技能、技能卡组属于 Phase 4，本阶段不做。

## 0. 开始前

1. 阅读 `AGENTS.md`、`docs/HOUSE_RULES.md`（尤其 U-ITEM、U-DICE）、`docs/phase3/Phase_3_局域网联机报告.md`。
2. `npm install`、`npm run build`，跑全部测试与 `verify:*`（含 `verify:lan-protocol`、`verify:lan-browsers`），确认基线全部通过再动手。
3. 所有截图验收必须使用 `scripts/screenshot-check.ts`。

## 1. 目标（验收以这些数字为准）

- **手机竖屏、单手**就能完整玩完一局；横屏只是可选。
- 主测机型：iPhone 13（390×844）和 Pixel 7（412×915），用 Playwright 自带的设备描述（含触屏）。
- 每个常见操作的**点击次数上限**（从"轮到我"到"操作完成"，不含掷骰动画）：

| 操作 | 上限 |
|---|---|
| 计划阶段选牌并提交（逃生者 1 张） | 2 次 |
| 计划阶段选牌并提交（杀手 2 张） | 3 次 |
| 移动到一个合法房间 | 1 次 |
| 翻开道具 / 与道具交互（修机、开门、躲柜、净化图腾、翻箱、放木板等） | 2 次 |
| 攻击 / 抓取 / 治疗另一位角色 | 2 次 |
| 技能时机询问：使用或跳过 | 1 次 |
| 结束本次行动 | 1 次 |
| 搬运路线（杀手） | 每一步 1 次 + 确认 1 次 |

- **全程不需要上下滚动页面**，也不需要用下拉框。
- 所有可点元素 ≥ 48×48 px；不依赖悬停；禁止双击缩放误触。

## 2. 第一步：手机操作审计（先做，做完停下给用户看）

在**现有界面**上，用 iPhone 13 尺寸把上表每个操作各做一遍，记录：实际点击次数、是否需要滚动、是否需要先在下拉框选房间、是否容易点错、文字是否看得清。

产出：
- `docs/phase2d/手机操作审计.md`：逐项表格 + 每项一张截图。
- `docs/phase2d/改版方案.md`：新的手机界面方案。**用真实页面做出可点的样稿**（可以先只覆盖计划、移动、交互三个场景，挂在 `/?view=mobile-preview`），每个场景附 iPhone 13 截图。

**做完第一步就提交 Git、报告并停止**，等用户确认方案后再继续第二步。

## 3. 第二步：按确认的方案实现

以下是建议方向，用户确认的方案优先。

### 3.1 画面分三层，一屏装下
- **顶部细条**（约 44px）：第几轮、当前阶段、发电机 x/4、献祭 x/8、联机状态。
- **中间棋盘**：占满剩余空间。镜头**自动跟随当前行动的角色**，只显示该房间及相邻房间；角色移动时镜头平滑跟过去。双指缩放、拖动照常；"全图"按钮一键看全局。
- **底部操作坞**（固定在屏幕底部，避开手机底部安全区）：**只显示"现在该你做的那一件事"**。
  - 计划阶段：手牌像扇形卡牌一样排在底部，点一张牌，棋盘上该颜色的路线和可到达房间发光；点"确认"提交。杀手依次点两张，牌上显示 1、2。
  - 移动阶段：可去的房间直接在棋盘上发光，**点房间就移动**，不再弹列表。
  - 交互阶段：底部弹出一排**大按钮**，每个按钮带道具图标和动词（"修理发电机""躲进储物柜""攻击 梅格"……），外加"结束行动"。不需要先点棋盘再找按钮；同时保留"直接点棋盘上发光的道具"这种方式。
  - 技能时机：底部弹出"是否使用『冲刺爆发』（1 血点）？"，两个大按钮"使用 / 跳过"。
  - 等待别人时：操作坞缩成一行"等待 杰克·朴 行动…"，棋盘照常可看。
- 去掉现在棋盘下方的"查看房间"下拉框、常驻图例和长文字面板。

### 3.2 信息按需出现
- 点自己的头像：底部抽屉展开角色卡（技能全文、血点、伤势、物品）。再点或下滑关闭。
- 点别人的棋子：显示对方的公开状态（伤势、血点、是否挂钩）。
- 事件日志：顶部下方一行"最新一条"的滚动字幕，点开看完整记录。
- 掷骰与反馈弹窗沿用 U-DICE：所有人同时看到翻滚动画，观看者自动关闭，行动者点一下继续。

### 3.3 轮到你时要能马上知道
- 轮到你：操作坞亮起并上浮，播放一声短提示音（设置可关），安卓震动一下，浏览器标签标题闪烁"轮到你了"。
- 屏幕常亮：对局中用 Wake Lock API 防止手机息屏（不支持的浏览器忽略）。
- 断线：顶部细条变红显示"重新连接中"，恢复后自动同步，不弹打断式提示框。

### 3.4 像 App 一样打开
- 加入 PWA 清单：可以"添加到主屏幕"，全屏打开，用原创灯笼图标；不做离线缓存游戏状态。
- `viewport` 禁止双击缩放（棋盘自己处理双指缩放）；使用 `env(safe-area-inset-*)` 适配刘海和底部横条。

### 3.5 在手机网络下也要快
- 现在 `dist/web` 约 147MB，主要是房间插画和道具 PNG。改为：
  - 房间插画转为 WebP，生成手机用小图（约 600px 宽）和电脑用大图，按屏幕加载；
  - 道具、头像图标压缩到合适尺寸（显示多大就做多大的 2 倍）；
  - 首屏只加载当前地图需要的图片。
- 目标：手机首次进入房间需要下载的总量 **≤ 8MB**；报告里给出改前改后的实际数字。
- 棋盘拖动、缩放时保持流畅（避免每帧重算全部 SVG）。

### 3.6 不能弄坏的
- 本机热座模式仍可用（可以共用新的手机界面）。
- 电脑端仍可正常玩，布局可以是"棋盘 + 右侧操作栏"，但操作逻辑与手机一致。
- 所有按钮仍然只调用规则引擎/服务器给出的合法操作，界面不自己算规则。

## 4. 验收（第二步完成时）

1. **点击次数测试**：新增 `scripts/verify-mobile-taps.ts`，用 iPhone 13 与 Pixel 7 两种设备、**只用触屏点击**，按回放跑完 4111 和 1701 两局联机对局（5 个浏览器，至少 2 个是手机）。脚本统计每类操作的实际点击次数，任何一项超过第 1 节上限即失败；同时断言整局没有发生页面滚动、没有使用下拉框。
2. 改前/改后对比表：每类操作的点击次数、首屏下载量。
3. 每个场景（计划、移动、交互、技能询问、等待、掷骰、搬运、结算）各一张 iPhone 13 截图，全部通过 `screenshot-check.ts`。
4. 原有全部测试与 `verify:*` 全部通过，包括 `verify:lan-protocol`、`verify:lan-browsers`。
5. 写 `docs/phase2d/Phase_2D_报告.md`，提交 Git，**报告并停止**。

## 5. 之后的顺序（本阶段不做）

- **Phase 4**：16 张物品效果（打出时公开，见 U-ITEM）、5 个待实现的板载技能、52 张技能卡组与 Bloodweb / Devout 模式。
- **Phase 5**：正式上云，固定网址，电脑可以关机。
