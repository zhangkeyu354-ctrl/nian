## 1. 新流程（只改回答方式，规则和计分照旧）
1. 发秘密数字：和现在一样。
2. **写答题卡**：除队长外，每人在自己的答题卡上写一个回答，写完点「提交」。
   - 答题卡**正面**是回答文字，**背面**是秘密数字。
   - 提交前可以随意修改。提交后显示「已提交」，在队长开始排序前可以「撤回修改」。
   - 字数限制 1–30 字，去掉首尾空格，不能为空。超过时输入框下方显示「最多 30 字」，并阻止提交。
3. **排序**：所有人提交后，队长看到全部答题卡的正面（回答文字 + 作者名），按 1→10 拖动或点选排序，然后确认。
   - 队长以外的人也能看到所有答题卡的正面（实体游戏里大家都能听到回答），但不能操作，只显示「队长正在排序…」。
   - 队长排序时，其他人的界面要实时同步卡片顺序，让大家看着队长排。
4. **揭晓**：按队长排好的顺序，逐张**翻卡**（3D 翻转，正面翻到背面显示秘密数字），排对绿光 + ✓，排错红光 + ✗。失误照规则书计算。
5. 专家模式（队长猜确切数字）：同样先写答题卡，队长看着卡片正面猜数字。

## 2. 引擎 / 协议 / 隐私
- 新命令：`SUBMIT_ANSWER {text}`、`WITHDRAW_ANSWER`。校验：只有非队长、在回答阶段、还没进入排序阶段才能提交；文本长度 1–30 字；队长不能提交。非法操作返回中文原因。
- 所有人都提交后（或房主计时到，按 CHECK_REQUIRED 默认处理：未提交的人卡面显示「（没写）」，照常参与排序），进入排序阶段。
- **隐私**：
  - 回答阶段，`viewForND` 只把自己的回答文字给本人；对其他人只给「已提交 / 未提交」。
  - 排序阶段起，所有人都能看到全部回答文字。
  - 秘密数字仍然只在揭晓时公开。
  - verify 脚本要检查回答阶段时别人的回答文字不出现在 DOM 和网络包里。
- 回答文本要转义后再显示，防止 XSS；日志不打印回答。
- 断线重连后，已提交的回答和未提交的草稿都要保留（草稿存本地 localStorage 并加 try/catch）。
- 本局回顾里显示每张卡的回答文字。

## 3. UI（覆盖 UI 验收文件的 A1、B7、B9）
- **写卡阶段（竖屏 390×844）**：
  - 上方：题卡（题目 + 1/10 两端标签），始终显示。
  - 中间：一张大答题卡，奶油纸质感、高约 200px。右上角显示自己的大号秘密数字徽章（可以点击遮住）。卡内是多行输入框，字号 20px，占位文字「写下你的回答…」，右下角显示字数「12/30」。
  - 底部主按钮：「提交答题卡」→ 提交后变成「已提交 · 撤回修改」（次按钮样式）。
  - 软键盘弹出时，答题卡和主按钮要留在可见区域，不能被键盘挡住（使用 visualViewport）。座位条在键盘弹出时可以先隐藏。
  - 队长看到的是「等大家写卡」+ 已提交人数的小圆点，不显示输入框。
- **排序阶段**：
  - 每张答题卡显示回答文字（主体，18px，最多 2 行）+ 作者名（小字），右侧有拖动把手「≡」，左侧是 1–10 的位置序号。
  - 卡片高度不低于 64px，9 人时排序列表可以滚动，题目条固定在顶部。
  - 非队长看到同样的列表，但处于只读状态，顶部显示「队长 X 正在排序」。
- **揭晓阶段**：以答题卡为主角，每行 2 张，按排序顺序翻开。翻开前显示回答文字，翻开后背面显示大号数字，回答文字缩小留在卡上。
