# 手机优先改版方案：第一步待确认

本次交付独立可点样稿，尚未替换正式对局。规则引擎、协议、privacy.ts、游戏数据、正式热座和联机界面保持原样。请先在手机上体验计划、移动、交互的布局，再决定是否进入第二步。

## 打开样稿

本机：`http://localhost:3000/?view=mobile-preview`。与电脑同一 Wi-Fi 的手机可尝试 `http://192.168.0.71:3000/?view=mobile-preview`；需要电脑上的现有服务运行。此地址是局域网地址，未进行实体手机与防火墙实测。

开发服务器也支持 `http://localhost:5173/?view=mobile-preview`。页面顶端明确标注“独立演示场景，未连接真实对局”；切换场景不会发送服务器命令。

## 一屏三层

- 顶部 48px 状态条：自己的头像、轮次/阶段、发电机与献祭进度。采用 48px 而非建议的约44px，确保头像热区合格。
- 中间：当前角色所在房间及全部相邻房间，合法目标和路线发光；“全图”按钮切换概览，再回到当前角色。邻接图来自合法回放的真实地图关系，样稿排布标为“邻接示意”，场景使用轻量占位，不能当作正式实物棋盘还原。
- 底部操作坞：只放本阶段的动作，固定底部并避开安全区。无下拉框，无页面滚动，不依赖悬停。

样稿的场景切换栏与演示提示用于评审；正式版移除它们，把空间还给棋盘。正式版镜头跟随行动者，保留拖动、双指缩放与一键全图。样稿不验证正式地图拖动性能。

## 确认后正式版的操作细节

| 情境 | 拟采用的入口与上限 |
|---|---|
| 翻道具、修机、开门、躲柜、净化、翻箱 | 底部显示服务器/引擎给出的合法动作；选动作+确认，最多2次；保留棋盘直点入口 |
| 放木板 | 选放木板，棋盘直接点合法路线提交，最多2次；取消不算完成 |
| 攻击、抓取、治疗 | 点带目标头像的动作，再确认，最多2次 |
| 技能时机 | 坞内显示名称、消耗与全文入口；使用/跳过直接提交，各1次；需目标的技能仅展示引擎给出的合法选择，不自行猜规则 |
| 结束行动 | 单个清晰按钮，1次 |
| 搬运 | 逐次点合法下一房间，每步1次，再确认1次；不能用下拉框选路线 |
| 等待与重连 | 坞收成等待提示，顶部显示连接状态；重连继续由现有协议同步 |

每一阶段只能由现有合法操作查询驱动，正式接入后重新验证。需要进一步选择才能使用的技能必须先核对目标与点击口径；不能为满足次数跳过规则选择。Phase 4的物品效果、复杂技能和技能卡仍不在本次范围。

信息按需展开：头像抽屉显示自己的技能、伤势、血点、物品；别人只显示公开状态。U-ITEM维持持有物品私密、打出后公开；U-DICE维持所有人看骰、观看者自动关闭、行动者点继续。整局点击验收将分别记录动作提交及骰子/反馈确认，不能把额外确认静默漏计。需要掷骰的单目标操作拟直接点动作提交，再点骰子继续，共2次；不再叠加一次事前确认。样稿的“选择+确认”只展示无额外反馈时的两步布局；涉及多目标、多次骰子等情境必须按真实完整流程验收，不能删掉规则要求来凑次数。

轮到自己提示音/震动、Wake Lock、重连状态条、PWA清单均留第二步实施；提供关闭设置和浏览器不支持时的降级。不做离线游戏状态缓存。热座与电脑端必须继续可用。

## 下载量方案

审计冷进入初始房间HTTP下载约57.73MB，中局约69.95–84.61MB；构建磁盘体积147.36MB。HTTP统计不含WebSocket，是实际全部网络流量的下界。正式版目前不满足≤8MB。

第二步拟生成约600px宽手机WebP与电脑大图，通过屏幕与当前地图按需选择；图标按实际显示尺寸的约2倍输出，只加载当前地图资源。按首次加入房间的完整流程测传输量，报告缓存禁用条件及WebSocket计量口径。样稿复用SVG占位的轻量结果不能替代正式美术版的8MB验收；本次没有批量压缩原素材。

## 第二步验收与停止点

用户确认本方案后才开始接正式界面。届时新增整局触控计数脚本，4111与1701两局、五个浏览器且至少两个手机设备描述；严格检查点击上限、无页面滚动、无下拉、≥48px热区。覆盖计划、移动、交互、技能、等待、骰子、搬运、结算截图，并重跑原有全部检查。当前只完成第一步，不能声称上述正式整局与网络目标已通过。
