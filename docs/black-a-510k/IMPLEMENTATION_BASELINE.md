# 双黑A五十K V1.1 Final 实施基线

本项目唯一玩法与验收依据：用户提供的《双黑A五十K V1.1 Final｜高品质开源资源与视听强化版》附件。本文不新增或改写房规。

## STAR 压力测试：Proceed

- 情境：现有桌游合集需要可远程联机、手机竖屏可完整操作的四人游戏。
- 张力：隐藏阵营、末墩和余牌分账、跨局交易、断线重试、资源许可和手机性能同时影响交付；现有生产站自动部署，不能在开发中推 `main`。
- 备选：不开发无法满足需求；仅静态或单机版本无法验收 T44；沿用现有 Socket.IO 房间基础设施并新建独立规则包能控制回归风险。
- 决策：按附件完整范围实施。前三项风险由规则与服务器测试、独立资源许可清单、隔离分支及预发布验收分别控制。

## PRD：已批准的需求

- REQ-001：仅开放四人、52张无王的 V1.1 冻结规则；验收 T01–T16。
- REQ-002：服务端权威地完成出牌、过牌、计分、阵营与终局；验收 T17–T32、T40–T43。
- REQ-003：连续局执行串行抽还交易，允许断线恢复和幂等重试；验收 T33–T39、T50–T56。
- REQ-004：接入现有大厅、房间、战绩与手机正式界面；验收 T44–T49、T57–T59。
- REQ-005：主动调研并采用许可明确的高品质资源，提供视觉与试听小样；验收 T60–T69。
- 非范围：六人和八人、AI 对手、付费系统、未经确认的地方房规、生产发布。
- 未决：地方规则真实性按附件第14节标为待反馈，不阻碍默认版；视觉方向需用户最终确认，未确认前 T58/T63 为 CHECK_REQUIRED。

## GROOVY 对齐：Aligned with Changes

- 目标、范围、结果：以附件第15.3节分级门槛验收，不以构建成功代替可发布。
- 责任：Codex 实施及记录测试证据；用户确认视觉与最终生产发布。
- 方案：在 `codex/black-a-510k-v11` 独立工作树开发，复用现有网站基础设施；规则包与现有游戏隔离。
- 风险：真机、弱网和四独立客户端需实测，缺证据时保持 CHECK_REQUIRED。
- 下一阶段：可以开始规则引擎和资源调研，正式视觉验收待确认。

## 设计基线

- 页面：大厅入口、房间准备、对局、15/17张赢家交换与11/9张输家状态、结算、规则与战绩。
- 视觉：按用户 2026-11-24 反馈提供深绿与明亮两套玩家可切换且持久化的配色；用统一的表面层次、光影和细边框提升质感，避免大幅背景贴图与素材拼贴。牌面保持清晰；最终视觉仍待用户看实际对局后确认。
- 交互：320/360/390/414px竖屏，手牌有效触控区至少44 CSS px；选中抬升、排序、合法提示、明确非法原因。动画和音效只响应服务端确认事件，断线重连不重播私密事件。
- 状态：加载、等待、自己行动、他人行动、超时托管、断线、错误、交易、结算及减少动态效果均须可识别。
- 不可变：隐藏手牌与阵营只由服务端白名单投影；动效不得驱动规则状态或泄露私密信息。
