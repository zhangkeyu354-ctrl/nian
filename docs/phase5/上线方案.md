# Phase 5 上线方案（Claude，2026-10-20）

目标：一个固定网址，电脑关着也能开房；手机直接打开；只发给朋友，不公开推广（游戏名称与卡文来自官方桌游，仅供私下游玩）。

## 1. 现状

- 服务器 `apps/server/src/main.ts`：一个 Node 进程同时提供网页（`dist/web`）和 Socket.IO 联机；端口取 `PORT`；房间存 `DBD_DATA_DIR`（默认 `data/rooms`）。
- 目前靠 `scripts/start-online.ps1` 在用户电脑上开 Cloudflare 临时隧道：免费，但电脑必须开着、每次链接不同。

## 2. 部署方式对比

| 方案 | 费用 | 优点 | 缺点 | 适合 |
|---|---|---|---|---|
| A. Render 免费网页服务 | 0 | 不要钱；连 GitHub 后推送即自动更新 | 15 分钟没人访问会休眠，再打开约等 1 分钟；没有持久磁盘，休眠/重启后房间消失（对局中有 WebSocket 消息不会休眠）；免费流量每月 5GB（每人进一局约 1.6MB，够用） | 朋友主要在日本/海外，能接受第一次打开慢 |
| B. Fly.io 东京 | 约每月 2–5 美元，需绑卡 | 一直在线、东京机房延迟低；可加小磁盘保存房间 | 没有免费额度 | 想要随时秒开 |
| C. 香港/东京小云服务器（如腾讯云轻量） | 约每月几美元 | 中国大陆访问通常最稳；完全可控 | 要维护系统；由 Claude 通过你的电脑远程管理 | 朋友主要在中国大陆 |
| D. 继续用电脑隧道 | 0 | 已经能用 | 电脑必须开着，链接每次变 | 过渡期 |

建议：先用 D 和朋友真机试玩一局 → 按朋友所在地选 A（海外，先免费）或 C（大陆）→ 嫌休眠再换 B。

## 3. 上线前代码准备（Claude 做，和选哪家无关）

1. 静态资源：补 `.webp`、`.webmanifest`、`.ico` 等 MIME；带哈希的 JS/CSS/图片加长期缓存，`index.html` 不缓存。
2. `/api/health` 健康检查。
3. 房间清理：超过 24 小时没动静的房间自动删除；限制同时房间数和每个连接的请求频率，防止被刷。
4. 生产配置：`DBD_ALLOW_FIXED_SEED` 关闭（测试房间不可用）；`DBD_PUBLIC_URL` 设为正式网址（邀请二维码用）。
5. `Dockerfile`（Node 24，先 build 再启动），A/B/C 通用。
6. 断线重连和刷新恢复座位在公网上复测（已有 `verify:lan-browsers`，改成可指定网址）。
7. 页面上显示版本号，方便判断朋友手机是否拿到新版。

## 4. 上线步骤

1. 用户只需要做：注册所选平台账号（以及 GitHub 账号，用于自动部署）。Claude 不能替用户注册账号或输入密码。
2. Claude：建私有 GitHub 仓库并推送代码 → 在平台上连接仓库、设环境变量、部署。
3. Claude：对正式网址跑 5 个浏览器的建房→选角→整局测试，并测刷新/断线恢复。
4. 用户和朋友用真手机打一局；问题汇总后修。
5. 以后更新：Claude/Codex 改完 → 推送 → 平台自动重新部署（几分钟）。对局中途部署会断开房间，尽量在没人玩时更新。

## 5. 风险

- 免费方案房间不持久：服务重启后进行中的房间丢失。
- 官方名称/卡文：只私下分享链接，不做搜索收录（加 `noindex`）。
- 真机兼容（iPhone Safari、微信内置浏览器）尚未实测，是上线后第一轮要看的。
