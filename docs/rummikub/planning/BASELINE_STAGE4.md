# 第 4 阶段设计与实现基线

来源：已通过的压力测试、阶段 2/3 需求及对齐、总指令 §4；本次“继续”授权实施既定 UI。使用 design-baseline、frontend-skill、tdd-builder、playwright。

视觉主张：深绿绒布上的象牙白实体牌，以暖木牌架承托，官方 Logo、笑脸和包装清楚可见。
内容计划：入口展示品牌/开房加入；大厅展示座位/房主设置/邀请；对局以桌面为主、手牌和一个确认按钮为辅；结算摊牌和累计积分。
交互主张：牌选中立即浮起，长按拖拽放大并显示目标插缝；提交后新牌 0.4s 入场、2s 黄光；deadline 圆环和最后秒数强调只用于可操作的真实状态。

## 状态与验收

- 手机 390×844：52px 顶栏、玩家条、可滚动缩放桌面，底部手牌 38×52/4px 间距、两行最多 18、超出内部横滚，64px 主操作坞，次操作独立一行避免遮牌。
- 横屏 844×390：桌面左 70%，右 30% 玩家/三列牌架/操作。桌面牌 30×42，电脑手牌 48×66、最大内容宽 1200。
- 无房/匿名/大厅/公开定先手/当前回合/破冰进度/非法草稿/别人回合/罚牌/结算/断线/请求中均有真实视图与中文状态。
- 私有编辑只走服务器草稿；点选多牌后新建或目标加号；拖拽同一 MOVE，旧桌面牌拖回牌架禁止。SPLIT 缝由独立剪刀控件，MERGE 通过组选择后合并。
- 复用 DM ActionDock 和 CountdownRing 的现有组件、drawing/feel.ts 的音效与震动；只在 rk.css 用 .rk-world 范围覆盖外观。不修改其他游戏引擎、样式。
- 菜单含音效/震动、规则、退出；本地偏好访问全部 try/catch。邀请复制失败给可选中文链接，不伪称已复制。
- 可点区域至少 44px（小牌外扩命中层，密集相邻牌保持独立指针区域；主按钮≥44），键盘 Enter/Space、aria 标签含颜色数字及选中状态；reduced-motion 关闭动画；对比度检查。
- 服务器 ack 之前禁重复，consumed:true 拒绝应用新快照；断线重连按 token 恢复，不用虚构的本地草稿。
- 自审图片按总指令两种手机方向各 12 状态，加桌面/18 张/20+组/首页盒子；测试用真实房间夹具进入状态，交互通过真实 UI 操作，不提供生产 fixture 后门。

明确边界：阶段 4 不改游戏规则；Q01–Q09 继续采用登记默认。公共入口必须可用，完整官方素材来源与清晰度/采色结果写 ASSETS。发现截图问题自行修正再截图。
