## 2. 美术：照着官方图重新画，做到"完美复刻"
目标是看起来就是官方桌游本身，而不是"AI 风格的仿制品"。

### 2.1 核心原则：全部重新生成，不裁剪、不直接用
1. **不裁剪，不直接用**：官方图（照片或扫描）只能当参考。游戏里用到的每一张图，都要照着官方图**重新画或重新生成**。不要从照片里裁一块、抠掉背景、调完色就直接放进游戏，原图再清晰也一样。
2. **临摹到一模一样**：
   - 构图、比例、配色、图案、线条、材质和文字位置都要和官方原图一致。
   - 原图里的反光、透视变形、噪点、手指和桌面在重画时直接去掉，按正视图来画。拍斜的地图板和卡牌，要按"从正上方看"的样子重画。
   - 不准自由发挥，不准加原图没有的元素，不准换画风。
3. **按游戏需要的尺寸生成**：按第 2.2 节的尺寸表直接以目标尺寸作画或生成。不要先做一张大图再随便缩，也不要拉伸变形。如果某个东西在官方图里的比例和游戏格子的比例不一样，就按游戏比例重新构图，但内容和风格保持一致，在报告里注明改了哪里。
4. **文字**：图上的中文要和中文版实物的印刷一致，字体风格也要接近。看不清的字标 `CHECK_REQUIRED`，不要猜。
5. **对比图**：每一张复刻图在报告里都要配一张「官方原图｜复刻」左右并排的对比图。

### 2.2 替换范围和输出尺寸
游戏里现在用到的位置都要换成复刻版。尺寸按下表输出（括号里是给高清屏用的 2 倍图，可选）：

| 用在哪里 | 现在的路径（参考） | 输出尺寸 | 格式 |
|---|---|---|---|
| 21 个房间的房间图（含新地图的房间） | `/assets/mobile/rooms/{id}.webp` | 600×400（2 倍 1200×800） | WebP |
| 地图封面（建房选地图时用） | `/assets/maps/{map}_cover.webp` | 768×512 | WebP |
| 13 名角色的立牌和头像（选角页、对局棋子、角色详情） | `portrait_*.webp` | 256×256（2 倍 512×512），透明背景 | WebP |
| 角色详情页的大立绘 | 新增 | 宽 512、高按立牌比例，透明背景 | WebP |
| 道具和标记图标（发电机、钩子、图腾等） | `/assets/items/*.webp` 等 | 256×256，透明背景 | WebP |
| 移动卡、物品卡、技能卡的正面和背面 | `back_*.webp` 等 | 按实物卡牌的长宽比，短边 256（2 倍 512） | WebP |
| 技能检定骰、危险骰的骰面 | 新增或替换 | 每个骰面 128×128（2 倍 256×256） | WebP |
| 大厅里黎明杀机的卡带封面 | `/assets/hall/dbd-card.webp` | 1200×900 | WebP |
| 大厅里黎明杀机的横幅封面 | `/assets/hall/dbd-wide.webp` | 1600×900 | WebP |

- 大厅的两张封面：参考官方包装盒和官方主视觉，**按大厅卡带的比例重新构图生成**，不要从包装盒照片上裁。
- 文件名和现有路径保持一致，替换掉旧图就能直接生效。新增的图在代码里接上。
- 表里没列到、但游戏里实际用到的图，按它现在的显示尺寸输出，并在报告里列出来。

### 2.3 统一要求
- **立牌感**：角色统一做成立牌，带浅色描边、底部柔和的接触阴影，光源方向统一。
- **光影统一**：大厅、场景、角色的光源方向一致，色调和现在的界面协调。
- **体积**：每张图尽量小于 300KB，房间图优先处理。压缩后肉眼要看不出差别。
- **回退**：保留原来的图作为回退。复刻图缺失时不报错、不白屏。
- **不要有"AI 味"**：
  - 不加粗黑描边，不加噪点或颗粒质感，不加多余的光晕。
  - 不要出现乱码字、多出来的手指、糊成一团的细节。

## 3. 补全地图（素材里有、游戏里还没有的地图）
对第 1 步清单里每一张「游戏里还没有」的地图，按下面的顺序做。

### 3.1 先转录地图数据，不碰画面
把地图写进 `packages/game-data/MAP_DATA.json`，格式和现有两张地图完全一样：
- **房间（nodes）**：
  - id（英文小写加下划线）
  - 中文名（按实物印刷）
  - 出生骰面
  - 每个房间道具格的数量和位置
- **路线（edges）**：
  - 起点和终点
  - 颜色（红 / 蓝 / 绿 / 黄）
  - 方向（双向，或单向从哪到哪）
  - 开局有没有墙
  - 是不是多房间路口
- **每一项都要带来源字段**：
  - `source_level`
  - `source_ref`：写素材文件名，并写明在图上的哪个位置
  - `status`
- 看不清或有歧义的路线标 `CHECK_REQUIRED`，写进 `docs/RULE_QUESTIONS.md`。**只要有一条路线是 `CHECK_REQUIRED`，这张地图就先不开放给玩家**（数据可以先提交）。
- 如果这张地图带有基础版规则里没有的特殊规则（比如特殊房间效果、特殊道具），**不要实现**。写进问题清单问用户，这张地图先暂停。

### 3.2 数据校验（必须全部通过）
- 写一个检查脚本，确认：
  - 路线数和房间数和素材一致。
  - 每个房间至少有一条路连出去。
  - 单向路的方向和图上的箭头一致。
- 用固定种子让规则引擎在新地图上自动跑至少 3 局完整对局，要求逃生者和杀手各至少赢 1 局，全程不报错。参考 Phase 1 的做法。

### 3.3 画面：用现在的「房间拼合」布局
- 在 `apps/web/src/boardLayout.ts` 里，照现有两张地图的写法给新地图加一份排布：
  - 房间写成左上角坐标加缩放：`[L, T, s]`。
  - 相邻的两个房间用「门」连接：`[房间A, 房间B, 路线id]`。
  - 实在没法相邻的房间用「小路」（corridors）连接。
- 要求：
  - 尽量让有路线相连的房间贴在一起，小路越少越好。
  - 房间有大有小，看起来真实一些，但最小的房间在手机上标题也要看得清。
  - 门的重叠段不能太短：控制台出现「门太窄」警告就要调整坐标。
  - 在手机竖屏 390×844 下整张图要铺满屏幕，既不能挤在一起，也不能被裁掉。
- 每个新房间都要有一张按第 2 节重新生成的房间图（600×400）。新地图也要有一张地图封面。

### 3.4 接入游戏
- 建房时可以选这张新地图，和现有两张地图并列。
- 出生骰、道具摆放、路线图标、单向箭头和开局的墙，都按 3.1 的数据显示。
- 在更新公告里加一条：新地图的名字，以及替换了哪些美术。
