# 《请留遗言》接入基线（2026-10-21）

## STAR：Proceed
S：熟人朋友希望在现有桌游合集远程玩，已有153张确认无字插画和15角色资料；手工共享图片不能保证秘密信息。
T：前三风险是原版细节歧义、秘密数据泄露、共用服务器回归；分别由规则来源记录、按人投影与多人测试、其他游戏回归负责。
A：纯手工成本低但易泄密；只加入口无法玩；独立游戏模块复用现有Socket.IO可降低重复维护。选择第三项，分支隔离，不推送线上。
R：Proceed，信心中等；用户已经明确要求加入现有网站。可进入PRD。

## PRD
目标：现有网站开房、手机独立加入并完成秘密身份与视觉证据推理一局。不做画像、推荐嫌疑人、内置语音、重新绘图。
REQ-001 大厅入口和路由：现有三款游戏入口不变，新增/?game=dm。
REQ-002 素材：153张按原cardId引用、游戏中无名称/标签；手机资源按显示尺寸派生，保留原PNG。
REQ-003 房间：4–10人、昵称、固定座位、准备、房主开始、刷新重连、服务器校验身份及版本、记录存档；非法/重复命令不得修改状态。
REQ-004 基础对局：随机角色→行凶→共同选真遗言→共同选假遗言→混洗→调查→第一次投票→辩解→第二次投票→处决→下回合/结算；两次必须同一人均过存活者半数才处决，死者无投票权。
REQ-005 角色：15种36实例资料完整，按已核对规则实现；需要共同选择时各参与人提交相同选择后才结算，允许提交前协商或修改；不收集自由文字遗言。
REQ-006 隐私：他人角色、凭证、证据来源、牌库种子不能发给无权客户端；公开死亡角色与终局揭晓。合法对象由服务器计算。
REQ-007 验收：规则单测、秘密投影、持久化重放、并发陈旧命令、4手机点击整局、原网站回归及构建。
范围：第一版4–10人；11–15人帮助卡未核实，不启用。互联网复用已有部署但本次不推main。公网是否发布另按用户要求。
依赖：说明书照片S04-S10、153卡清单、发行方同版36角色104证据说明书。统计只记录局内命令，不涉及玩家现实特征。
可进入GROOVY。

## GROOVY：Aligned with Changes
依据用户完整框架指令、照片位置确认和“加入桌游网站”的本次实施授权；不据PRD存在本身推定同意。
用户负责审美/规则裁定；Codex负责实现与验证。成功标准为真正多人对局，不是静态页面。
决定：独立dm引擎/房间/协议/UI，原三游戏规则和协议不改；用户原153图不覆盖。先本地通过再报告。缺失11–15人配置为已明确边界。
待定：高级角色极端全员连锁组合未获清晰例子，必须专项验证；不得以“已录入”代替已实现。可进入设计基线。

## Design baseline
视觉主张：奶油纸面与黑墨线，珊瑚红主要操作，现有卡片做核心视觉；游戏首页以一张大卡和标题/建房入口组成，证据选择才使用卡片网格。
交互：手机顶部房间号/轮次，中间当前阶段和私人动作，证据图3列，桌面最多5列；证据无可见卡名，使用位置编号的无障碍标签。头像仅为座位圆标，不使用现实外貌。
首屏建房/加入；大厅昵称+准备+固定座位+人数；游戏身份默认遮挡可点开。非当前操作者明确显示等待。提交中禁重复、离线禁提交，错误以role=alert显示，返回大厅不暗中重置对局。
投票先私下提交，全部完成才公布统计；第一次过半后给一次辩解机会。公开证据与历史分区，真假只在有权能力/终局展示。
触控目标至少44px，可见键盘focus；360px无横向溢出，图片保持3:4，减弱动画设置受系统偏好控制。
使用事件驱动状态转换，不按计时器强行跳过玩家行动；查看真证据有独立确认窗口，不把真伪发给所有人。
基线完成；用户本次已经明确要求实施，可进入TDD。

## 用户追加：圆桌和发言（2026-10-21）
圆桌固定座位号1起，房主调整角色池而非指定玩家身份；开局随机分发。死亡私屏展示所有杀手，技能按窗口先执行再进入证据。公开遗言后按存活座位号顺序发言，每人5分钟，当前发言人可提前结束；服务端到时自动轮换，全部结束才允许投票。这是用户明确指定的线上流程，取代自由讨论自行开票的初稿。角色池在开始前可编辑，游戏中锁定。
