# Phase 3 局域网联机报告（Claude 完成，2026-10-19）

Codex 额度用完期间由 Claude 完成。规则引擎（`engine.ts`、`skills.ts`、地图/角色数据）未改动，只新增了"按座位隐藏信息"的视图函数。

## 怎么玩

1. 在电脑上双击项目根目录的 **`启动局域网联机.cmd`**。
   - 第一次会自动安装依赖（需要网络，之后断网也能玩），然后构建网页、启动服务器，并自动打开浏览器。
   - 命令行窗口会显示局域网地址和二维码。Windows 防火墙弹窗时，勾选"专用网络"并允许。
2. 在电脑浏览器里"创建房间"：选地图、人数、角色。会得到一个 4 位房间号和二维码。
3. 朋友的手机连**同一个 Wi-Fi**，扫二维码（或打开地址后输入房间号），选一个座位。
4. 每个人只在自己的设备上操作自己的角色。计划阶段所有人同时秘密选牌；轮到别人行动时，你的屏幕显示"等待某某行动"，棋盘照常可见。
5. 刷新页面、手机锁屏、断网重连，都会自动回到原座位。服务器重启后，房间也会从存档恢复。

本机热座模式仍然保留（首页），首页右上角新增"联机对战"入口。

## 实现

| 部分 | 文件 | 说明 |
|---|---|---|
| 隐藏信息 | `packages/game-engine/src/privacy.ts` | `viewFor(state, 座位)`：随机种子与随机数状态、未翻开道具的种类、别人的手牌和未亮出的计划牌、物品牌库、别人的物品，全部替换为 `hidden`（保留数量）。 |
| 协议 | `packages/shared/src/protocol.ts` | 建房、加入、选座、提交命令、状态推送五种消息。 |
| 服务器 | `apps/server/src/main.ts`、`rooms.ts` | Node + Socket.IO，同时提供网页。每条命令都校验：座位凭证 → 版本号 → 角色归属 → 规则引擎。任一项失败都不改变状态。 |
| 前端 | `apps/web/src/net.ts`、`Online.tsx`、`App.tsx` | 联机大厅、选座、二维码邀请；棋盘复用热座界面。 |
| 启动 | `启动局域网联机.cmd`、`scripts/start-lan.ps1` | Windows 一键启动。 |

### 几个关键决定

- **随机种子由服务器生成**，玩家无法指定。否则知道种子就能算出所有道具和骰子。只有用 `DBD_ALLOW_FIXED_SEED=1` 启动的测试服务器才接受固定种子。
- **版本号用"已执行命令数"，而不是事件数**。"不使用技能，继续"这类命令不产生事件，如果用事件数，双击会被执行两次。测试中发现了这个问题并已修正。
- **存档只保存创建参数和命令列表**（`data/rooms/房间号.json`），重启时按确定性规则引擎重放恢复。没有用 SQLite：私人局域网对局量很小，JSON 加原子写入更简单，也不需要额外的原生依赖。上线到互联网时如有需要再换。`data/` 已加入 `.gitignore`。
- **储物柜占用者身份不作为秘密**：规则原文要求把逃生者棋子放在储物柜上，实体游戏里大家都看得见。界面仍只显示"被占用"，但服务器不额外隐藏。
- **物品牌只对持有者可见**：规则书没有明说，先按保守处理。逃生者之间可以口头沟通。如需改成公开，只要改 `privacy.ts` 一行。

## 顺带修复

- 笔记本等较矮屏幕（如 1366×900）上，"全图"时棋盘超出一屏、底部房间被切掉。现在电脑端棋盘高度不超过一屏，并居中显示。

## 还没做 / 需要你确认

1. **在真实设备上试一次**：测试都在模拟浏览器里完成。请用自己的电脑和至少一台手机实际连一次，确认防火墙和 Wi-Fi 没有问题。
2. 联机时，每个人的画面仍然是现在这套热座界面（下方面板、按钮）。"桌面化改版"（Phase 2D）按计划放在联机之后做。
3. 骰子和反馈弹窗会出现在所有人的屏幕上，每个人各自点"已查看"。这样大家都能看到结果；如果觉得打扰，可以改成观看者自动消失。
4. Phase 4（物品效果、5 个复杂技能、技能卡组模式）与 Phase 5（互联网部署）未开始。
